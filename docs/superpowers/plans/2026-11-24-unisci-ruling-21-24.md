### Task 1: Busta RCSY a blocchi (Ruling 24)

**Files:**
- Create: `src/Recordum.Data/Sync/ChunkedAesGcmEnvelope.cs`
- Modify: `src/Recordum.Data/Sync/SyncFileCipher.cs` (usa la busta nuova), `src/Recordum.Data/Sync/SyncService.cs`
  (`Classify`), `docs/formats/sync-file.md` §1.1
- Test: `tests/Recordum.Data.Tests/Sync/ChunkedEnvelopeTests.cs`; restano verdi `SyncFileCipherTests`, `SyncServiceTests`

**Interfaces:**
- Produces: `internal sealed class ChunkedAesGcmEnvelope` con
  `ChunkedAesGcmEnvelope(ReadOnlySpan<byte> magic, Func<EnvelopeErrorKind, string, Exception> createException,
  Func<string, byte[], ushort, byte, byte, Task<byte[]>> deriveKey, int chunkSize = DefaultChunkSize)`,
  `Task EncryptAsync(Stream input, Stream output, string passphrase, ReadOnlyMemory<byte> fixedSalt, CancellationToken ct)`,
  `Task DecryptAsync(Stream input, Stream output, string passphrase, CancellationToken ct)`,
  `internal const int DefaultChunkSize = 1 << 20`, `internal const byte FormatVersion = 0x02`.
  `SyncFileCipher` mantiene la sua API pubblica: nessun chiamante cambia.
- Consumes: le costanti e `DeriveKeyArgon2idAsync` di `AesGcmEnvelope` (header da 41 byte, limiti KDF), `EnvelopeErrorKind`.

**Formato deciso** (va nel documento così):
- Header identico per layout (41 byte), byte 4 = `0x02`. Il chunk size **non** sta nell'header: con la versione 2 è
  fisso a 1 MiB (il parametro del costruttore serve solo ai test).
- Il corpo è una sequenza di blocchi `ciphertext_i ‖ tag_i` (tag 16 B). Ogni blocco tranne l'ultimo ha esattamente
  `chunkSize` byte in chiaro; l'ultimo ne ha **da 0 a chunkSize − 1** (se il chiaro finisce sul confine si scrive un
  ultimo blocco vuoto). Così un blocco pieno non è mai l'ultimo e il lettore non deve guardare avanti.
- Nonce del blocco `i` = nonce dell'header XOR (`7 byte a zero ‖ BE32(i) ‖ 0x01 se ultimo, altrimenti 0x00`).
- AAD di ogni blocco = i 41 byte dell'header (autentica versione e parametri KDF).
- Il lettore scrive il chiaro blocco per blocco: chi chiama scarta l'uscita se `DecryptAsync` lancia (è già così:
  `SyncService` decifra su un temporaneo che distrugge, `SyncSettingsViewModel` sposta solo a operazione riuscita).
- Nessun tetto sul cifrato (la memoria è costante); restano i limiti KDF e i tetti del lettore dello ZIP.
- Versione `0x01` → `UnsupportedVersion` (file di prima della 1.0, solo sulle macchine di prova). Versione `> 0x02` →
  nuovo `EnvelopeErrorKind.NewerVersion` (in fondo all'enum: la busta del backup non lo usa), che
  `SyncFileCipher.CreateException` traduce in `SyncFormatException` con `isNewerMajorVersion: true`; `Classify` lo
  traduce già in `NewerFormat`.

- [ ] **Step 1: Test che falliscono** (in `ChunkedEnvelopeTests`, chunkSize 16 per i casi di confine):
  - `Round_trip_for_sizes_around_the_chunk` — teorie su 0, 1, 15, 16, 17, 48, 1000 byte: il chiaro torna identico.
  - `Truncation_at_a_chunk_boundary_is_rejected` — si cifra 48 byte, si tagliano gli ultimi 16 B (l'ultimo blocco, vuoto):
    `SyncFileException` con `Error == CannotOpen`.
  - `Swapped_chunks_are_rejected`, `A_trailing_byte_after_the_final_chunk_is_rejected`,
    `A_changed_header_byte_is_rejected` (byte 11, iterazioni, ancora nei limiti) → tutti `CannotOpen`.
  - `Wrong_passphrase_writes_nothing` — l'uscita resta lunga 0.
  - `A_version_1_envelope_is_rejected` → `SyncFileError.UnsupportedEnvelope`.
  - `A_newer_envelope_version_reports_newer_format` → `SyncFormatException { IsNewerMajorVersion: true }`.
  - `Decrypting_64_MiB_allocates_little` — chunkSize di default; 64 MiB casuali cifrati prima in un `MemoryStream`,
    uscita `Stream.Null`: `GC.GetTotalAllocatedBytes(precise: true)` intorno a `DecryptAsync` cresce < 16 MiB (misura,
    non deduzione: CLAUDE.md §7; non per thread, perché `await` cambia thread). In una `[Collection]` non parallela;
    `[Trait("Category", "Performance")]` solo se supera 2 s in locale.

  non compila (la classe non c'è).

- [ ] **Step 3: `ChunkedAesGcmEnvelope`** come sopra; `SyncFileCipher` la costruisce al posto di `AesGcmEnvelope`.

### Task 2: Eco una volta (Ruling 21)

**Files:**
- Modify: `src/Recordum.Data/Sync/SyncSnapshot.cs` (`SyncManifest`), `src/Recordum.Data/Sync/SyncArchiveWriter.cs`
  (`SyncWriteOptions`), `src/Recordum.Data/Sync/SyncService.cs`, `docs/formats/sync-file.md` §2.1 e §6

  `CleanupAfterNoOpMergeConverges`), `tests/Recordum.Data.Tests/Sync/SyncServiceTests.cs`

**Interfaces:**
- Produces: `SyncManifest.DataSignature` — `[JsonPropertyName("data_signature")] public string? DataSignature { get; init; }`
  (assente = null); `SyncWriteOptions` riceve `string DataSignature`; impostazione `sync.acked_data`
  (JSON `device_id → data_signature`), costante `AckedDataSettingKey` in `SyncService`.
- Consumes: `ComputeSignatureAsync` (la firma che oggi decide se riscrivere: è quella che va nel manifest).

**Regola:**
- Dopo l'unione riuscita del file di un pari: se `manifest.DataSignature != acked[peer]` il giro deve scrivere il proprio
  file anche se l'unione non ha cambiato niente (`WriteOwnFileIfChangedAsync(merged: merged || echoNeeded)`), e
  `pending[peer] = manifest.DataSignature`.
- `acked ∪= pending` si salva **solo dopo** che il proprio file è stato scritto (Review Focus 3); con `ownFileIsForeign`
  non si salva.
- Il file scritto porta `data_signature` = la firma salvata in `LastWrittenSignatureSettingKey`, quindi un'eco ha la stessa
  firma del file prima e chi la riceve non risponde.
- "Parti dai dati degli altri" (`emptyFirst`) svuota `acked` come svuota `mergedFrom`; `DisconnectAsync` toglie
  `sync.acked_data` insieme alle altre chiavi.
- Va tolto il commento "merged_from non entra nella firma…" sopra `WriteOwnFileIfChangedAsync`, sostituito da una riga sul
  perché dell'eco.

- [ ] **Step 1: Test che falliscono:**
  - `CleanupAfterNoOpMergeConverges` senza `Skip` (lo scenario di Neon ALTA 1 c'è già).
  - `Echo_happens_once_then_stops` — due dispositivi; A cambia un dato; giri A, B, A, B, A, B: `OwnFileWritten` vale
    `true, true, false, false, false, false` (A scrive il cambio, B l'eco, poi silenzio).
  - `Echo_with_three_devices_stops_after_one_round` — A cambia; giri B, C, A, B, C, A, B, C: B e C scrivono una volta
    ciascuno, poi tutti `false`.
  - `Ack_is_saved_only_after_the_own_file_is_written` — store finto la cui `WriteOwnAsync` lancia `IOException` al primo
    giro: al secondo giro (store sano) B scrive l'eco.
  - `Manifest_carries_the_written_signature` — il `data_signature` letto dal file scritto è uguale a
    `LastWrittenSignatureSettingKey`.
