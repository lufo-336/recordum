# Milestone 3.7 — Habit Detail Screen (design)

**Status**: draft · 2026-05-22
**Predecessor**: M3.6 (Journal Editor + Notes), main @ 88b57b8
**Successor**: M3.8 (Streaks Engine — depends on `IStreakAggregator` introduced here)
**Schema delta**: **none** — milestone is read-side + UI only; `schema_version` stays `2.5`.

## 1. Goal

Add a third **Detail** tab to `HabitScreen` that surfaces analytical views of a habit's history: year-long heatmap with proportional intensity, streak summary + 90-day timeline, trend chart (line/area or bar), 24-hour distribution, and goal progress card. Pays back the M3.3 known limit (binary heatmap intensity step) and the implicit promise in CLAUDE.md §7 milestone 3.7 scope.

**Non-goals:**
- Full streak engine (deferred to M3.8). M3.7 ships a deliberately naïve daily aggregator.
- Cross-children aggregation for `Group` nodes (only goal progress card visible for groups).
- Third-party chart library (M3.9 introduces LiveCharts2 as core plugin pilot consumer of `chart.renderer`). M3.7 uses pure WPF `Canvas` + shape primitives so the chart engine choice in M3.9 is not pre-empted.
- Detail tab visible on Trash tab (it follows the existing Completion/Notes pattern — Trash retains its own row context menu).

## 2. Surface

`HabitScreen.xaml` evolves from 2 tabs (Completion / Notes) to 3 (Completion / **Detail** / Notes). The Configure button, the WebView2-missing banner, the 5-column MainWindow layout, and the existing TimerStatusBar are untouched.

Detail tab vertical composition (top→bottom):

1. **GoalProgressCard** — compact 1-row card.
2. **YearHeatmap** — 53 cols × 7 rows ending today, proportional ramp.
3. **StreakSummary** — three stat cards (Current / Longest / Runs in 90d).
4. **StreakTimeline** — 90-day horizontal bar lane.
5. **TrendChart** — line+area or bar, range selector `30d | 90d | 1y` (chips top-right).
6. **HourlyHistogram** — 24 vertical bars, hour-of-day distribution.

Hidden-for-group rule: when `NodeType == Group`, sections 2–6 collapse; only the `GoalProgressCard` renders (showing an empty-state message if the group has no active goal).

## 3. Architecture

### 3.1 Data flow

```
                    ┌──────────────────────────────────────────┐
                    │            DetailViewModel               │
                    │  (ctor: services + IEventBus + IClock)   │
                    └─┬──────────┬──────────┬──────────┬──────┬┘
                      │          │          │          │      │
                      v          v          v          v      v
            ┌─────────────┐ ┌────────────┐ ┌─────────┐ ┌──────────┐ ┌──────────────┐
            │GoalProgress │ │YearHeatmap │ │ Streak  │ │  Trend   │ │   Hourly     │
            │  Card VM    │ │    VM      │ │ + Time- │ │  Chart   │ │  Histogram   │
            │             │ │            │ │ line VM │ │   VM     │ │     VM       │
            └─────┬───────┘ └─────┬──────┘ └────┬────┘ └────┬─────┘ └─────┬────────┘
                  │               │             │           │             │
                  v               v             v           v             v
           IGoalService  IIntensityRamp  IStreakAggregator ITrendQuery IHourlyDist
                                +
                          IDailyAggregate (heatmap rollup, may reuse ICompletionService.GetHeatmapAsync)
```

`DetailViewModel.LoadAsync(HabitNode node)` orchestrates `Task.WhenAll` of all visible child `LoadAsync` calls, gated by visibility rules.

### 3.2 Event-bus reactivity

`DetailViewModel` subscribes (in ctor, disposed in `Dispose`) to:

- `CompletionRecorded` / `CompletionUpdated` / `CompletionDeleted` (filter by `HabitNodeId == current.Id`) → reload `YearHeatmap`, `Streak*`, `Trend`, `Hourly`, `Goal`.
- `NoteCreated` / `NoteUpdated` / `NoteDeleted` (filter by `HabitNodeId`) → reload `Trend` (Journal habits) and `Goal` (when goal counts notes — heuristic: `MetricDefinitionId == null && HabitType == Journal`).

No debounce. Payloads are scarce and `LoadAsync` is idempotent.

### 3.3 Group nodes

`DetailViewModel.IsGroup = node.NodeType == NodeType.Group`. The `Detail` `TabItem` itself stays visible (consistent with Completion behaviour for groups, which already accepts groups via M3.5 row click). Internal sections set `Visibility = Collapsed` when `IsGroup` except `GoalProgressCard`.

### 4.2 `GoalProgressCardViewModel`

```csharp
public sealed partial class GoalProgressCardViewModel : ObservableObject
{
    [ObservableProperty] string name = "";
    [ObservableProperty] decimal actual;
    [ObservableProperty] decimal target;
    [ObservableProperty] string unitLabel = "";
    [ObservableProperty] double percentComplete; // 0..1+, can exceed 1
    [ObservableProperty] string periodLabel = "";
    [ObservableProperty] int? daysLeft;
    [ObservableProperty] bool isDone;
    [ObservableProperty] bool isEmpty;
    [ObservableProperty] string emptyMessage = "";

    [RelayCommand] private Task OpenConfigureAsync(); // raises event consumed by HabitScreenViewModel
}
```

Period computation per `GoalPeriodType`:

| Type | Range | DaysLeft |
|---|---|---|
| `Fixed` | `[PeriodStart, PeriodEnd]` clamped to today | `PeriodEnd - today` if positive |
| `Rolling` | `[today - RollingDays + 1, today]` | `null` |
| `Open` | `[habit.CreatedAt → today]` | `null` |

Actual computation:
- `MetricDefinitionId != null` → sum of `CompletionValue.ValueNumeric` over completions in range matching the metric. Average for State (single-value scale, `ValueInteger` averaged).
- `MetricDefinitionId == null` → count of completions in range (Action/Journal-style).

Empty state: `Goal == null` → `IsEmpty = true`, `EmptyMessage = Strings.Detail_GoalCard_NoGoal_Title + " — " + Strings.Detail_GoalCard_NoGoal_Hint`. View renders empty layout with a link button bound to `OpenConfigureCommand`.

### 4.3 `YearHeatmapViewModel`

```csharp
public sealed partial class YearHeatmapViewModel : ObservableObject
{
    public ObservableCollection<HeatmapCellViewModel> Cells { get; } = [];
    public Task LoadAsync(HabitNode node, CancellationToken ct = default);
}
```

- Range: 53 weeks back from today, anchored to weekday Monday (locale-agnostic — week starts Mon to match GitHub/Notion convention; out of scope to localize week start).
- Total cells = 53 × 7 = 371 (some leading + trailing days outside the year are still rendered, intensity = step 0, tooltip shows date but click is suppressed by `IsBeforeAnchor` / `IsAfterToday` flag).
- Source: `ICompletionService.GetHeatmapAsync(node.Id, from, today)` → `IReadOnlyList<HeatmapCell>` already aggregating daily count. For Counter/Resistance/State proportional ramp, an additional projection is needed (sum of primary metric value per day). Two options considered:
  1. Add `GetDailySumAsync(habitNodeId, primaryMetricId, from, to)` to `ICompletionService`.
  2. Extend `HeatmapCell` with optional `Sum`.
  - Chosen: **option 1** — `ICompletionService.GetDailySumAsync(Guid habitId, Guid metricId, DateOnly from, DateOnly to)` returns `IReadOnlyList<DailyValue>(Date, Sum)`. Falls back to `GetHeatmapAsync` when habit has no primary metric (Action/Journal — Count-based ramp).
- Intensity assignment uses `IIntensityRampResolver.Resolve(node, config, activeGoal)` → 4 breakpoints (Step1..Step4) + step 0 for value 0. Cell's `IntensityStep ∈ {0,1,2,3,4}` matches the existing `IntensityStepToBrush` converter from M3.5 (no new brushes).
- Tooltip: `"{Date:yyyy-MM-dd} — {Value} {UnitLabel or 'completions'}"`.

The existing 13-week `HeatmapViewModel` in the Completion tab is also upgraded: its `LoadAsync` now resolves the same `IIntensityRampResolver` to switch from the binary fallback to proportional steps when a goal exists. No layout change to the Completion tab.

## 5. Services

### 5.1 `IStreakAggregator` (new in `Recordum.Core.Abstractions.Services`)

```csharp
public interface IStreakAggregator
{
    ValueTask<IReadOnlyList<StreakRun>> GetHistoryAsync(
        Guid habitNodeId,
        DateOnly fromDate,
        DateOnly toDate,
        CancellationToken ct = default);
}

public sealed record StreakRun(DateOnly Start, DateOnly End, int Length);
```

Impl. `NaiveDailyStreakAggregator` in `Recordum.Data.Services.Aggregators`:
- Reuses `ICompletionService.GetHeatmapAsync(habitNodeId, fromDate, toDate)` for raw daily counts (no extra SQL).
- Linear scan: any day with `Count >= 1` is "active". Consecutive active days form a run. First gap closes a run.
- Returns runs ordered ascending by `Start`.
- **Ignores** `HabitConfig.ScheduleType`, `StreakMode`, `StreakRecovery`, `StreakPause`. This is the M3.7 known limitation. The View shows `Strings.Detail_BasicStreakNotice` for habits whose `ScheduleType != Daily` so the user understands the limitation.
- DI: `Scoped`.

M3.8 will introduce a replacement `SchedulingAwareStreakAggregator` registered against the same interface — the ViewModels need no change.

### 5.2 `ITrendQueryService` (new)

```csharp
public interface ITrendQueryService
{
    ValueTask<IReadOnlyList<TrendPoint>> GetTrendAsync(
        Guid habitNodeId,
        DateOnly fromDate,
        DateOnly toDate,
        TrendGranularity granularity,
        CancellationToken ct = default);
}

public sealed record TrendPoint(DateOnly Bucket, decimal Value, int Count);
public enum TrendGranularity { Daily, Weekly }
```

Impl. `TrendQueryService` in `Recordum.Data.Services.Queries`:
- Resolves primary metric via `IMetricDefinitionService.ListByHabitAsync(habitId)` ordered by `SortOrder`, taking first.
- For Counter/Resistance: `Value = SUM(CompletionValue.ValueNumeric WHERE MetricDefinitionId == primary.Id)`.
- For State: `Value = AVG(CompletionValue.ValueInteger WHERE MetricDefinitionId == primary.Id)` (decimal average to preserve fractional points).
- For Action/Journal: `Value = Count`.
- Daily bucket key: `date(completed_at)` (DB-side). Weekly bucket key: ISO-week Monday (client-side after fetching daily — keeps SQL portable to other engines later).
- Empty buckets: not returned (the View pads with zero when iterating the range).
- DI: `Scoped`.

### 5.3 `IHourlyDistributionQueryService` (new)

```csharp
public interface IHourlyDistributionQueryService
{
    ValueTask<IReadOnlyList<int>> GetHourlyAsync(
        Guid habitNodeId,
        DateOnly fromDate,
        DateOnly toDate,
        CancellationToken ct = default);
}
```

Impl. `HourlyDistributionQueryService` in `Recordum.Data.Services.Queries`:
- SELECT `CompletedAt` for completions in range with `IsRetroactive = 0`.
- Client-side: convert each `CompletedAt` (UTC) → local time via `IClock.LocalTimeZone`, bucket by `Hour`.
- Returns `int[24]`. DI: `Scoped`.

### 5.4 `IClock.LocalTimeZone` (extension)

Add `TimeZoneInfo LocalTimeZone { get; }` to `IClock`. `SystemClock` returns `TimeZoneInfo.Local`. Test fakes (`TestClock` etc.) accept a `TimeZoneInfo` in the constructor (default `TimeZoneInfo.Utc` for determinism). This keeps the no-direct-`DateTime.Now` rule intact for the hourly bucket conversion.

### 5.5 `IIntensityRampResolver` (new in `Recordum.Core.Abstractions`)

```csharp
public interface IIntensityRampResolver
{
    IntensityRamp Resolve(HabitNode node, HabitConfig? config, Goal? activeGoal);
}

public sealed record IntensityRamp(decimal Step1, decimal Step2, decimal Step3, decimal Step4);
```

Impl. `IntensityRampResolver` in `Recordum.Core.Services`:
- If `activeGoal != null && activeGoal.TargetValue > 0` ⇒ steps `(0.25T, 0.5T, 0.75T, 1.0T)` where `T = activeGoal.TargetValue` normalized to per-day (Fixed/Rolling: divide by period length; Open: keep raw).
- Otherwise fallback `(1, 3, 7, 8)` (matches existing M3.5 `0, 1, 2-3, 4-7, ≥8` breakpoints).
- Pure C#, stateless, no EF deps. DI: `Singleton`.

## 6. Rendering — pure WPF

All chart controls are `UserControl` (`Recordum.WPF.Controls`) bound to their respective ViewModels via DPs. No `OnRender` overrides — primitives are `Rectangle`, `Polyline`, `Polygon`, `Button`, hosted in `Canvas` or `ItemsControl`.

### 6.1 Controls

| Control | Container | Primitives | Notes |
|---|---|---|---|
| `YearHeatmapControl` | `ItemsControl` rows=7 cols=53 (UniformGrid FlowDirection=LeftToRight) | `Button` per cell, `Background = IntensityStep` (reuses M3.5 converter) | Cell 11×11 px + 1px margin. `ScrollViewer` wraps when pane <660 px. |
| `StreakTimelineControl` | `Canvas` Height=24 | `Rectangle` per run | `X = (Run.Start - RangeFrom).Days * DayWidth`, `Width = Length * DayWidth`, `Fill` = habit accent (resolved via `HabitNode.Color`, fallback `Brush.Accent`). |
| `TrendChartControl` | `Canvas` MinHeight=180 | `Polyline` + `Polygon` (line); `Rectangle`s (bar); `TextBlock` axis labels | `Points` DP triggers full `Canvas.Children.Clear()` + redraw. Y axis 4 ticks (0, ¼max, ½max, ¾max, max). X axis 3–5 evenly spaced date labels. |
| `HourlyHistogramControl` | `ItemsControl` Horizontal Orientation | `Rectangle` per hour, fixed Width, Height = `Count/MaxCount * MaxBarHeight` | Tooltip `"{Hour:00}:00 — {Count}"`. |

All brushes resolved via `DynamicResource` so dark/light theme works via the existing `Resources/MergedDictionaries` swap. No hardcoded colors.

### 6.2 Tooltips

Set `ToolTipService.InitialShowDelay=300` on all chart primitives (the WPF default is too slow). Localized formatting via `Strings.*` keys.

### 6.3 Accessibility

`AutomationProperties.Name` on every chart primitive (e.g. `"Heatmap cell, 2026-05-22, 3 completions"`). Tooltips supplement screen reader output.

## 9. Open trade-offs (resolved)

- **Heatmap range 365 vs 371**: chose 53 weeks × 7 = 371 to keep the grid rectangular. Leading days outside the year are rendered with `IntensityStep = 0` and `IsBeforeAnchor = true` (click suppressed; tooltip still shows date).
- **State trend aggregation**: `AVG`, not `SUM` — a scale value is a level, not a quantity. Resistance/Counter use `SUM`.
- **Goal target per-day normalization**: Fixed/Rolling divide by period length, Open keeps raw target. Avoids the year-long heatmap reaching "100%" intensity on day one of a long-period goal.
- **Hourly retroactive filter**: `IsRetroactive` completions stamp at midnight UTC, which would skew the histogram. Filter excludes them.
- **`IClock.LocalTimeZone`**: minor extension preserves the "no direct `DateTime.Now`" rule.

## 10. Known limits (carried forward to next milestones)

- **Streak engine is naive** — daily-only, ignores `weekly_target` / `schedule_days` / `recovery` / `pause`. M3.8 replaces `NaiveDailyStreakAggregator` with the full engine behind the same `IStreakAggregator` interface; the View needs no change. The `Detail_BasicStreakNotice` localized banner makes the limitation explicit to the user.
- **No cross-children aggregation for groups** — only `GoalProgressCard` renders. Group-level rollups (sum of children completions) deferred indefinitely until a clear use case emerges.
- **Year heatmap week start hardcoded to Monday** — locale-aware week start (Sunday for en-US conventions) deferred. The brief explicitly references GitHub-style heatmap, which is Monday-anchored.
- **No animation on chart redraw** — by design, per the brief's "motion restrained" rule.
- **Single goal per habit** — `IGoalService.GetActiveAsync` already returns one. Multi-goal stacking is out of scope.
