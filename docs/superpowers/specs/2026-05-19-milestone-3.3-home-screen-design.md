# Milestone 3.3 — Home Screen (design)

**Status**: approved 2026-05-19 (brainstorming).
**Depends on**: Milestone 3.1 (schema + plugin foundation), Milestone 3.2 (Core Data Layer + SQLCipher).
**Schema delta**: introduces v2.4 (`pin_scope` on `habit_node`, `home_tree_row` projection extension).

---

## 1. Context

Milestone 3.3 is the first user-facing UI of Recordum. It produces the **Home Screen**: the single window the user sees on launch. The data layer (3.2) is complete and provides all services needed for read-side operations; 3.3 wires those services to a WPF MVVM view.

Several adjacent capabilities are explicitly deferred to later milestones to keep 3.3 shippable as a self-contained increment:

- **Habit creation / editor** → Milestone 3.4
- **Completion recording (5 types, session mode, retroactive)** → Milestone 3.5
- **Habit Detail screen (heatmap with custom range, streak history, chart, hourly distribution, goal progress)** → Milestone 3.7
- **Streak engine (placeholder `CurrentStreakCount = 0` in projection until then)** → Milestone 3.8
- **Custom charts / tag-map / Obsidian-style graph** → Milestone 3.9
- **Export / backup-restore UI** → Milestone 3.10

These are routed by name in §10. Home Screen 3.3 is a **viewer + organizer**: it shows the existing habit tree, allows the user to filter, search, navigate, reorder, rename, pin, archive, soft-delete, and restore — but does not create habits or record completions.

---

## 2. Principles

In addition to the project invariants in `CLAUDE.md` §2:

1. **Read-first surface.** Home 3.3 must remain fast and quiet. No animations, no progress bars beyond a single loading state, no toast notifications.
2. **No UI placeholders.** Anything visible on screen must actually work. Buttons or rows that would require 3.4 / 3.5 features are not shown at all rather than disabled.
3. **English-first, italiano secondario.** All UI strings via `Strings.resx` (en) + `Strings.it.resx` (it). No hardcoded literals.
4. **Light + dark, system-follow default.** The user can override theme in Settings; the override is persisted.
5. **Keyboard-first parity.** Every mouse-only action has a keyboard equivalent.
6. **Single window.** No multi-tab workspace metaphor. The "tab nav" of the milestone summary maps to three view filters (Active / Archived / Trash), not multiple workspace tabs.

## 3. Scope

### 3.1 In scope

- Single `MainWindow` shell: top bar + filter row + habit tree.
- Three view filters as a segmented control in the top bar: **Active** · **Archived** · **Trash**.
- Filter row controls: Sort (Manual / Name / Last completion), Type (multi-select), Tag (multi-select), Hide-completed-today toggle, live Search (name only).
- Habit tree:
  - `HabitNode` hierarchy from the existing services.
  - Per-row anatomy: 4 px accent bar (left, color = `HabitNode.Color`), optional pin icon prefix, name, type label (small, right), 7-day inline heatmap (right end, last cell = today, outlined).
  - Group rows: expander caret, name, child count. No heatmap on groups. No status indicator.
- Pin model: `PinScope` enum **None | Local | Global**.
  - `Global` pinned float above all groups.
  - `Local` pinned float to the top of their parent group (or to the top of the root list if they have no parent).
  - Pinned items are sorted among themselves by the current sort option.
- Drag-and-drop reorder within a parent and across parents (Move).
- Context menu on a habit row: Rename · Pin → (None / Local / Global) · Archive · Soft-delete.
- Context menu on a group row: Rename · Archive · Soft-delete.
- Context menu in the Trash tab: Restore · Purge (calls `IPurgeService` for the single subtree).
- Inline rename via `F2` or double-click on the name.
- Keyboard shortcuts: `F2` rename, `Delete` soft-delete, `↑`/`↓` selection, `→`/`←` expand/collapse, `Ctrl+F` focus search, `Ctrl+1`/`Ctrl+2`/`Ctrl+3` switch tab.
- Light/Dark/System theme; manual override persisted in `AppSetting`.
- Empty state: friendly message localized en/it.
- Error state: message + Retry button if `GetHomeTreeAsync` fails.
- `ApplicationInitializer` integration: Home is the default content after bootstrap.

## 4. UI

### 4.1 Window shell

`MainWindow` is a single non-resizable-below-`880×620` window. Layout is a vertical `Grid`:

```
+--------------------------------------------------+
| Top bar          [Active | Archived | Trash]   ⚙ ⋮
+--------------------------------------------------+
| Sort ▾  Type ▾  Tag ▾  ☐ Hide completed   🔍 …  |
+--------------------------------------------------+
|                                                  |
|  Habit tree (virtualised TreeView)               |
|                                                  |
+--------------------------------------------------+
```

### 4.2 Top bar

Components, left → right:
- App name "Recordum" (`FontWeight=600`, 15 px).
- Segmented control: `Active` (default) · `Archived` · `Trash`. Selected tab gets a 2 px underline in the accent color. Inactive tabs are 60 % opacity.
- Spacer.
- Settings icon (`Lucide.Settings`) → opens dropdown with theme toggle + About.
- Menu icon (`Lucide.MoreVertical`) → opens dropdown with About + Quit. (Import / Export deferred.)

### 4.3 Filter row

Below the top bar, on the same surface. Compact (13 px, 0.85 opacity until hovered).

- **Sort** dropdown: Manual (default, sorts by `HabitNode.SortOrder`) · Name (A→Z) · Last completion (most recent first; `null` last).
- **Type** dropdown (multi-select): Action / Counter / Resistance / Journal / State. Default = All.
- **Tag** dropdown (multi-select): lists all tags from `tag` table. Default = All.
- **Hide completed today** checkbox: filters out habits where `IsCompletedToday` is true. Visible only on the Active tab.
- Search box: live filter on `Name` (case-insensitive, contains). Debounced 200 ms.

Filter state is reset on tab switch (Active / Archived / Trash don't share filters because the underlying domain is different).

### 4.4 Tabs

| Tab | What it shows |
|---|---|
| Active | `pin_scope` not constrained · `is_archived = false` · `deleted_at IS NULL` |
| Archived | `is_archived = true` · `deleted_at IS NULL` |
| Trash | `deleted_at IS NOT NULL` |

In Active, the tree is hierarchical (groups + nested habits). In Archived and Trash, the tree is **flat** (no grouping) — restoring respects original parent.

### 4.5 Habit row

```
│  ║  📌  Habit name          counter  □□▤▤▤■■■(today)
↑   ↑   ↑   ↑                  ↑       ↑
indent  pin icon              type     7-day heatmap
4px accent bar (color)        label
```

- Indent: 0 for root nodes, 24 px per nesting level.
- Accent bar: 4 px wide, full row height, color = `HabitNode.Color` (hex).
- Pin icon (`Lucide.Pin`): rendered if `PinScope ≠ None`. Pin global is rendered slightly differently (filled vs outlined) so the user distinguishes the two.
- Habit name: regular weight, 14 px. Pinned: medium weight.
- Type label: 12 px, 50 % opacity, lowercase ("action" / "counter" / "resistance" / "journal" / "state").
- 7-day heatmap: 7 cells, 10 px × 10 px, 2 px gap, 2 px radius. Cells from left = oldest → today. Today is outlined (1 px solid, `text` color). Color = 5-step GitHub ramp:
  - 0 completions → faint background (≈ 8 % opacity of accent in dark, similar in light)
  - 1 / 2 / 3 / ≥4 → progressively saturated accent
  - For counter / resistance: intensity ≈ `min(1, sum_value / target)` of the day (target from `HabitConfig`).
  - For action / journal / state: binary present/absent → step 1 or step 0.

### 4.6 Group row

Same indent rules as habit rows. Includes:
- Expander caret (`Lucide.ChevronRight` / `Lucide.ChevronDown`) on the far left after the indent.
- Group name (semibold).
- Child count (12 px, 50 % opacity, " 4 habits" form).
- No accent bar (groups don't have a color in `HabitNode` despite the field — by convention, groups inherit the neutral surface stroke). Decision: groups still respect `HabitNode.Color` but render the bar at 60 % saturation to differentiate from leaves.

No heatmap, no pin icon (groups can also be pinned and the pin icon is shown if so — same rule as habits).

### 4.7 Loading / Empty / Error

- **Loading** (first paint after tab switch or app start): centered `ProgressRing` (24 px) + label "Loading…". No tree visible. Resolution target: < 300 ms (data layer p95 budget).
- **Empty** (after load, zero rows):
  - Active tab → "No habits yet. Habit creation arrives in milestone 3.4."
  - Archived tab → "Nothing archived."
  - Trash tab → "Trash is empty."
  - Centered, 16 px, 60 % opacity. No call-to-action button (would be a UI placeholder in 3.3).
- **Error**: centered `Lucide.AlertTriangle` (32 px, warning color) + localized error message + "Retry" button (re-runs `LoadAsync`). Underlying exception logged at `Error` level.

### 4.8 Context menu

Triggered on right-click anywhere on the row (excluding the heatmap, which has no interaction in 3.3 — its tooltip shows `<date>: <n> completion(s)`).

| Tab | Habit row | Group row |
|---|---|---|
| Active | Rename · Pin ▸ (None / Local / Global) · Archive · Soft-delete | Rename · Archive · Soft-delete |
| Archived | Rename · Unarchive · Soft-delete | Rename · Unarchive · Soft-delete |
| Trash | Restore · Purge | Restore · Purge |

Pin submenu shows a checkmark next to the current scope. Selecting the same scope is a no-op.

Keyboard equivalents:
- `F2` → Rename
- `Delete` → Soft-delete (Active/Archived) or Purge (Trash, with `Confirm` dialog)
- `Ctrl+E` → Archive / Unarchive (toggle by tab)
- `Ctrl+R` → Restore (Trash only)

### 4.9 Drag-and-drop

In the Active tab only.

- Drag a habit row → drop on a group row = move under that group as new last sibling (also sets `SortOrder` to max+1 of siblings).
- Drag a habit row → drop between two siblings = insert at that position (renumber `SortOrder` of affected siblings).
- Drag a group row → same rules. Dropping a group inside its own descendant is prevented (already enforced by `IHabitNodeService.MoveAsync` cycle guard; UI shows a "not allowed" cursor and rejects the drop with no DB call).

Visual feedback: drop target row gets a 1 px insertion line above/below (sibling drop) or full-row outline (parent drop).

Implementation: handlers on `TreeViewItem` (`PreviewMouseLeftButtonDown` to arm, `MouseMove` with 5 px threshold to start drag, `DragOver`/`DragLeave`/`Drop` on hover targets). No external library.

### 4.10 Keyboard

| Key | Action |
|---|---|
| `↑` / `↓` | Move selection up / down in the visible tree |
| `→` | Expand selected group, or move into first child |
| `←` | Collapse selected group, or move to parent |
| `Home` / `End` | Jump to first / last row |
| `F2` | Rename selected node |
| `Enter` | Same as `F2` |
| `Esc` | Cancel inline rename / dismiss context menu |
| `Delete` | Soft-delete selected (in Active/Archived) or Purge with confirm (in Trash) |
| `Ctrl+F` | Focus search box |
| `Ctrl+1` / `Ctrl+2` / `Ctrl+3` | Switch tab Active / Archived / Trash |
| `Ctrl+E` | Toggle archive on selected (Active ↔ Archived) |
| `Ctrl+R` | Restore selected (Trash only) |

### 4.11 Theming

Theme is a `ResourceDictionary` swap at runtime. `App.xaml` merges a `Tokens.xaml` (semantic names — `--bg`, `--surface`, `--border`, `--text`, `--text-muted`, `--accent`) and a theme dictionary (`Light.xaml` or `Dark.xaml`) that defines the values.

Modes:
- **System** (default): query `AppsUseLightTheme` from `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize`; subscribe to `SystemEvents.UserPreferenceChanged` to react to changes without restart.
- **Light** / **Dark**: explicit override, persisted in `AppSetting` (key `theme.mode`, value `system|light|dark`).

The 7-day heatmap uses `HabitNode.Color` as the accent for each cell; intensity is computed in HSL by adjusting lightness against the theme background to stay within readable contrast in both themes.

### 4.12 Localization

All UI strings via `Recordum.WPF.Resources.Strings.resx` (English, default) and `Strings.it.resx` (Italian). Resource keys are prefixed by view: `Home.TopBar.Active`, `Home.Filter.SortLabel`, `Home.ContextMenu.Rename`, etc.

Number / date formatting uses `CultureInfo.CurrentUICulture`. `IClock` is the source of "today" — never `DateTime.Now`.

### 5.2 ViewModels

All VMs use `CommunityToolkit.Mvvm` (`ObservableObject`, `[ObservableProperty]`, `[RelayCommand]`).

#### `MainWindowViewModel`

- Holds the current `HomeViewModel` instance, the `SettingsViewModel`, and dispatches to them.
- Subscribes to `IThemeService.ModeChanged` to swap the active `ResourceDictionary`.
- Exposes commands for the top-bar menu items (About, Quit).

#### `HomeViewModel`

- Observable properties:
  - `ActiveTab : HomeTab` (`Active` | `Archived` | `Trash`)
  - `SortOption : HomeSort` (`Manual` | `Name` | `LastCompletion`)
  - `TypeFilter : ImmutableHashSet<HabitType>` (empty = all)
  - `TagFilter : ImmutableHashSet<Guid>` (empty = all)
  - `HideCompletedToday : bool`
  - `SearchText : string`
  - `Rows : ObservableCollection<HomeRowViewModel>` (flat for UI binding; visual nesting from `IndentLevel` on each row)
  - `SelectedRow : HomeRowViewModel?`
  - `State : HomeState` (`Loading` | `Loaded` | `Empty` | `Error`)
  - `ErrorMessage : string?`
- Commands:
  - `LoadCommand` async — calls `IHabitTreeQueryService.GetHomeTreeAsync(ct)`, applies the tab-specific predicate, builds the row VM list with computed `IndentLevel` / `IsPinnedAboveOthers` ordering, then sets `State`.
  - `SwitchTabCommand`, `SetSortCommand`, `ToggleTypeFilterCommand`, `ToggleTagFilterCommand`, `ToggleHideCompletedCommand`, `SearchChangedCommand` — each marks the in-memory list dirty and re-applies the filter pipeline (no DB roundtrip unless tab changed). Search is debounced 200 ms.
  - `RetryCommand` — alias for `LoadCommand` when `State == Error`.
- Lifecycle: instantiated by DI as scoped per the existing `Recordum.WPF` DI setup. Disposes the `CancellationTokenSource` for in-flight loads on disposal.

#### `HomeRowViewModel`

- Wraps one row from the (extended) `HomeTreeRow` projection plus `PinScope` + the 7-day completion counts.
- Observable properties:
  - `HabitNodeId : Guid`
  - `ParentId : Guid?`
  - `Name : string` — observable to support inline rename
  - `Color : string` (hex)
  - `HabitType : HabitType?`  (`null` for groups)
  - `IsGroup : bool` ≡ `HabitType is null`
  - `IsExpanded : bool` (groups only; persisted only in-memory for 3.3)
  - `IndentLevel : int`
  - `PinScope : PinScope`
  - `LastCompletionAt : DateTime?`
  - `IsCompletedToday : bool`
  - `CompletionsLast7Days : ImmutableArray<int>` (length 7, oldest → today)
  - `ChildCount : int` (groups only)
  - `IsArchived : bool`
- Commands (all delegate to the matching service in `Recordum.Data.Services`):
  - `BeginRenameCommand` / `CommitRenameCommand` / `CancelRenameCommand`
  - `SetPinScopeCommand(PinScope)` — single command takes the target scope, no separate pin/unpin commands.
  - `ArchiveCommand` / `UnarchiveCommand`
  - `SoftDeleteCommand`
  - `RestoreCommand`
  - `PurgeCommand`
  - `MoveToCommand(Guid? newParent)` — used both by drag-drop completion and by the "Move to…" dialog if added later (3.4 reuse).
- Each command, on success, mutates the underlying property and lets `HomeViewModel` decide whether to re-load the whole list (e.g., a move requires re-sort) or just update the row.

#### `SettingsViewModel`

- `ThemeMode : ThemeMode` (`System` | `Light` | `Dark`), bound to `IThemeService` + persisted to `AppSetting` (`theme.mode`).
- `Version : string`, `Licenses : string` (static for now).
- `OpenLogFolderCommand`, `AboutCommand`.

### 5.3 Data flow

```
MainWindow ─► HomeView (ContentControl bound to HomeViewModel)
HomeView      uses TreeView with HierarchicalDataTemplate
              binds to HomeViewModel.Rows
              ContextMenu, DragDrop, KeyBindings -> HomeRowViewModel commands

HomeViewModel ─► IHabitTreeQueryService.GetHomeTreeAsync()
               ─► IHabitNodeService (rename / move / softdelete / restore / archive / pin)
               ─► IPurgeService (purge from Trash)
```

Filtering and sorting are applied **client-side** on the `Rows` collection because:
- The tree is bounded by the user's habit count (typical < 200, perf-tested up to 200×50k completions). Filtering 200 items in C# is microseconds.
- The 7-day heatmap data is already loaded once per `LoadAsync`; re-filtering doesn't need a roundtrip.
- Tab switch is the only case that triggers a new DB roundtrip (different `deleted_at` / `is_archived` predicate).

### 5.4 Settings popup

Anchored under the `Settings` icon. Width 280 px, no chrome (popup).
Contents:
- Theme radio group: System / Light / Dark.
- "About Recordum" link (opens a `MessageBox` for 3.3, replaced by a proper About dialog later).

No "Templates" section (out of scope; the empty state hint about templates is removed from the spec — it would be a UI placeholder).

## 6. Data-layer changes — schema delta v2.4

### 6.1 `PinScope` enum

New file `src/Recordum.Core/Enums/PinScope.cs`:

```csharp
namespace Recordum.Core.Enums;
public enum PinScope { None, Local, Global }
```

### 6.2 `HabitNode` model

Replace `IsPinned` with `PinScope`:

```csharp
// before
public bool IsPinned { get; set; }
// after
public PinScope PinScope { get; set; }
```

### 6.3 EF migration

`Migrations/2026XXXXXXXXXX_PinScope.cs`:

1. Add column `pin_scope TEXT NOT NULL DEFAULT 'None'` to `habit_nodes` with `CHECK (pin_scope IN ('None','Local','Global'))`.
2. `UPDATE habit_nodes SET pin_scope = 'Local' WHERE is_pinned = 1;`
3. Drop column `is_pinned`. SQLite requires table recreation; EF handles this via `RenameTable` / `CreateTable` / `DropTable` sequence — verify the generated SQL keeps the `pin_scope` data.
4. Update `AppSetting.schema_version` from `2.3` → `2.4`.

The migration is destructive of the `is_pinned` column. CLAUDE.md §7 says "nessuna migrazione invasiva" after Fase 3 — within Fase 3 the schema is still being finalized, and this is the last column-level rename before the schema is frozen.

### 6.4 `HabitNodeConfiguration`

Replace the `is_pinned` Fluent mapping:

```csharp
builder.Property(n => n.PinScope)
    .HasConversion<string>()
    .HasMaxLength(8)
    .HasDefaultValue(PinScope.None);

builder.HasIndex(n => n.PinScope);   // home query hot path

builder.ToTable(t => t.HasCheckConstraint(
    "ck_habit_node_pin_scope",
    "pin_scope IN ('None','Local','Global')"));
```

The existing `HasIndex(n => n.DeletedAt)` and `HasIndex(n => n.ParentId)` remain.

### 6.5 `HomeTreeRow` DTO extension

`src/Recordum.Core/Abstractions/Services/Dtos/HomeTreeRow.cs`:

```csharp
public sealed record HomeTreeRow(
    Guid HabitNodeId,
    Guid? ParentId,
    string Name,
    string ColorHex,
    HabitType? HabitType,
    DateTime? LastCompletionAt,
    int CurrentStreakCount,                       // still 0 until 3.8
    bool IsCompletedToday,
    PinScope PinScope,                            // new
    int ChildCount,                               // new (groups; 0 otherwise)
    bool IsArchived,                              // new
    ImmutableArray<int> CompletionsLast7Days);   // new (length 7, oldest → today)
```

### 6.6 `HabitTreeQueryService` extension

`GetHomeTreeAsync` is extended:

- Adds the new fields above to the projection.
- Adds a 7-day window grouped sub-query: for each `HabitNode`, count completions per day between `today − 6` and `today` (inclusive), produce `int[7]`. Implemented as a correlated `SELECT` per day or a single `GROUP BY day, habit_node_id` followed by a join — choice deferred to plan time after micro-benchmark.
- `ChildCount` for groups: a correlated count of direct children.
- Filtering: tab predicate (Active / Archived / Trash) is the only filter applied in SQL. All other filters (Type / Tag / HideCompleted / Search) are applied client-side on the VM.

Perf budget remains p95 < 300 ms over the seeded dataset (200 habits, 50 k completions). The 7-day group-by is the riskiest change — the existing composite index `(habit_node_id, completed_at_ms)` already supports it. If the new query exceeds budget, fall back to a separate per-row aggregation call.

### 6.7 Sorting contract

The home view defines the canonical sort:

```
1. PinScope == Global  (sorted among themselves by current sort option)
2. PinScope == Local   (sorted among themselves by current sort option, grouped under their parent)
3. Everything else     (sorted by current sort option, hierarchy preserved)
```

Implementation lives in `HomeViewModel`, not in SQL — keeps the projection stable and lets the user re-sort without a DB roundtrip.

## 8. Acceptance criteria

1. **Tab switching** between Active / Archived / Trash works; each tab shows the correct subset and triggers a single DB roundtrip.
2. **Pin model** — `PinScope` enum present, migration applied, sorting respects Global → Local → other.
3. **Heatmap inline** — 7 cells per habit row, today outlined, color derived from `HabitNode.Color`, intensity matches the `CompletionsLast7Days` projection.
4. **Filter row** — Sort / Type / Tag / Hide-completed / Search all work client-side without re-querying the DB (except tab change).
5. **Context menu** — Rename / Pin submenu / Archive / Soft-delete / Restore / Purge each maps to the right service call and the view reflects the new state without a full reload where possible.
6. **Drag-and-drop** — Reorder within parent and across parents persist `SortOrder` / `ParentId` and refresh the tree.
7. **Keyboard parity** — All shortcuts in §4.10 work.
8. **Theming** — System / Light / Dark all render correctly; system-follow reacts to OS change at runtime; manual override survives restart.
9. **Localization** — Switching `CurrentUICulture` to `it-IT` renders Italian strings end-to-end with no fallback to English in 3.3 surfaces.
10. **Empty / Loading / Error** — each state renders correctly and is reachable in tests.
11. **Perf** — `GetHomeTreeAsync` p95 < 300 ms on the seeded 200×50 k dataset after the extension.
12. **Build clean** — zero warnings, all tests green (Core + Data + Plugins + WPF), no analyzer regressions.

## 9. Known risks and follow-ups

- **Drag-and-drop on `TreeView`**: WPF's built-in TreeView has rough edges for DnD (auto-scroll, drop visualization). The plan must allocate enough budget for the behavior + integration tests on at least the move-across-parent path.
- **System theme watcher** can leak `SystemEvents.UserPreferenceChanged` if not unsubscribed on app exit — `ThemeService` must be a singleton and unsubscribe in its `Dispose`.
- **`PinScope` migration on existing dev DBs**: developers running 3.2 builds locally must let EF apply the migration; the test for this case is in §7.2.
- **Heatmap intensity formula for counter/resistance**: the formula `min(1, sum_value / target)` requires reading `HabitConfig.TargetValue`-like fields. If the projection grows too heavy, the plan can fall back to a binary "any completion that day" rendering and restore the proportional intensity in 3.7.
- **Inline rename collisions**: two users editing the same DB via sync (Fase 5) would race. Not relevant for 3.3 (single-user Windows), explicit note for the sync milestone.
