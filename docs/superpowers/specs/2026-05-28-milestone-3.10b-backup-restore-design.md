# Milestone 3.10b — Backup / Restore — Design

> **Status:** approved design, pre-plan. Part of roadmap Milestone 3.10 (Export + Backup/Restore), **split** into 3.10a (Export, shipped 2026-05-28) and 3.10b (Backup/Restore, this doc). Closes the offline-first promise: the user must be able to fully snapshot and recover Recordum without any cloud component.

## 1. Goal

Give the user a complete, encrypted, portable snapshot of their Recordum installation — DB, attachments, and the manifest of which plugins were active — that can be restored on the same machine after a mistake or on a fresh installation after a hardware change. Add an unattended **auto-backup** loop (weekly by default, retention 8) so the user is protected even when they forget.

Backups are sealed with an Argon2id-derived AES-256-GCM envelope, machine-independent, single-file `.recbak`. Restore always takes a safety snapshot of the pre-restore state before overwriting anything.

The plugin manifest snapshot inside the backup is the **first concrete consumer of `IPluginManager.ListActivatedManifests()`** — in Phase 3 it lists the two core plugins (Chart Engine, Export Engine) registered at startup; in Phase 7 it will additionally cover sideloaded plugins and their persisted permission decisions. The on-disk backup format already reserves a `Permissions` section that is empty in Phase 3 and populated in Phase 7 — **the format does not need to bump when Phase 7 lands**.

## 2. Scope

**In scope:**

- Manual **Create backup** and **Restore backup** from the top nav.
- **Backup history** workspace (paged DataGrid backed by a new `backup_log` table).
- **Auto-backup scheduler** with DPAPI-wrapped sticky passphrase, default weekly, retention 8.
- New `RecordumOptions.AttachmentsDirectory` + `BackupsDirectory` + `AutoBackupKeyPath`. Attachments directory is populated by future milestones (no upload UI in Phase 3); backup already snapshots it so the format is stable.
- New `.recbak` container format (magic `RCBK`, AES-256-GCM envelope, Argon2id KDF) — single file, ZIP body containing `manifest.json` + `db/recordum.db` + `attachments/<id>.<ext>`.
- Pre-restore safety snapshot (`pre-restore-{ts}.recbak`) always created before overwriting.
- Schema delta v2.6 → **v2.7** with a single additive migration `BackupLogV27` (one new table + 5 new `AppSetting` rows).
- 22 new resx keys (en + it).

**Out of scope (deferred):**

- Cloud sync / cross-device sync (Phase 5).
- Incremental or differential backup (full only — Recordum DBs are small).
- Restore selection: per-habit or per-date-range (Phase 8+).
- Persisted plugin install table or persisted permission decisions (Phase 7) — the backup format already reserves room for these.
- Backup of WebView2 cache / plugin IndexedDB (Phase 7).
- A template-builder UI for retention rules.

## 3. Architecture

No new assembly. Code lands in existing projects:

| Project | Role |
|---|---|
| `Recordum.Core` | `Backup/` namespace: `IBackupService`, `IRestoreService`, `IBackupScheduler`, `BackupManifest`, `BackupOptions`, `BackupResult`, `RestorePreview`, `RestoreReport`, `BackupKind` enum, `BackupException`, `RestoreException`. Plus `Abstractions/Security/IBackupCipher`. C# pure, zero EF/UI deps. |
| `Recordum.Data` | `Backup/` namespace: `BackupService`, `RestoreService`, `BackupArchiveWriter/Reader`, `AesGcmBackupCipher` (Argon2id + AES-GCM envelope), `BackupScheduler`, `BackupLogService`. Plus migration `BackupLogV27` and `BackupLog` model. |
| `Recordum.Plugins` | Extend `PluginManager` with `ListActivatedManifests()` tracker (`Dictionary<string, PluginManifest>` updated in `EnableAsync` / `DisableAsync`). |
| `Recordum.WPF` | `Bootstrap/BackupSchedulerHost.cs` (singleton, started after `ApplicationInitializer`). `ViewModels/Backup/` (4 VMs). `Views/Backup/` (4 dialogs/view). Top-nav extension, DI, i18n. |

**Deviation (documented):** `BackupService` and `RestoreService` live in **`Recordum.Data`, not Core**, because they need a live `RecordumDbContext` for the `VACUUM INTO` plain-dump path and for writing the `backup_log` row. Same rationale as `IChartQueryService` (M3.9) and `IExportQueryService` (M3.10a) — the abstraction is in Core, the impl lives where the DB does. This keeps Core free of EF Core entirely.

## 4. Container format — `.recbak`

A single binary file. Layout, big-endian where applicable:

```
  +------------------------------+
  | magic        4B   "RCBK"     |
  | version      1B   0x01       |
  | reserved     3B   0x00       |
  | kdf_id       1B   0x01       |  // Argon2id
  | kdf_mem_mib  2B   64         |
  | kdf_iters    1B   4          |
  | kdf_parallel 1B   2          |
  | salt        16B   random     |
  | nonce       12B   random     |
  | ciphertext   N    AES-256-GCM of inner ZIP
  | tag         16B   AES-GCM tag
  +------------------------------+
```

Header is plain (not encrypted) so we can read KDF params before deriving the key. Magic + version let us reject foreign files immediately and bump the container format later without breaking history.

**Inner ZIP** (plain DEFLATE, what AES-GCM encrypts):

```
manifest.json
db/recordum.db                    (plain SQLite, produced via VACUUM INTO)
attachments/<guid>.<ext>          (copied verbatim from AttachmentsDirectory)
```

`manifest.json` schema:

```jsonc
{
  "schema_version": "2.7",
  "app_version": "3.10.0",
  "created_at_utc": "2026-05-28T14:32:11Z",
  "kind": "Manual",                          // Manual | Auto | PreRestore
  "size_bytes_uncompressed": 12345678,
  "counts": {
    "habits": 42, "completions": 51230,
    "notes": 18, "attachments": 0
  },
  "plugins": [
    { "plugin_id": "io.recordum.chart-engine",  "version": "3.10.0", "enabled": true,  "sideloaded": false },
    { "plugin_id": "io.recordum.export-engine", "version": "3.10.0", "enabled": true,  "sideloaded": false }
  ],
  "permissions": {                           // empty {} in Phase 3, populated in Phase 7
    "grants_by_plugin": {}
  }
}
```

## 6. Schema delta — v2.6 → v2.7

**Single additive migration** `BackupLogV27`:

```sql
CREATE TABLE backup_log (
    id              TEXT PRIMARY KEY,                  -- GUID
    created_at      TEXT NOT NULL,                     -- ISO 8601 UTC
    kind            TEXT NOT NULL CHECK (kind IN ('Manual','Auto','PreRestore')),
    path            TEXT NOT NULL,                     -- absolute path on disk
    size_bytes      INTEGER NOT NULL,
    schema_version  TEXT NOT NULL,                     -- e.g. "2.7"
    app_version     TEXT NOT NULL,
    notes           TEXT NULL
);
CREATE INDEX ix_backup_log_created_at ON backup_log (created_at DESC);
```

Bump `app_setting` row `schema_version` from `2.6` to `2.7` inside the migration.

**New `AppSetting` keys** seeded by `AppSettingSeed`:

| Key | Default | Notes |
|---|---|---|
| `backup.auto.enabled`           | `true` | Scheduler on by default. |
| `backup.auto.frequency_days`    | `7`    | Range 1..90 (validated in UI). |
| `backup.auto.retention_count`   | `8`    | Range 1..100. |
| `backup.auto.last_run_utc`      | (empty) | Updated by scheduler. |
| `backup.auto.path`              | empty → resolves to `BackupsDirectory` | User can override to external drive. |

The Phase 3 user is logged in via DPAPI by default, so seeding `enabled=true` is safe: until the user sets an auto-backup passphrase, the scheduler is *configured but inert* (see §10 for the inert state).

## 8. Backup creation flow

```
caller (UI or scheduler)
  └─ BackupService.CreateAsync(destinationPath, passphrase, options, ct)
       1. Validate destinationPath writable; create parent dir if missing.
       2. tempDir = Path.Combine(Path.GetTempPath(), "recordum-bk-" + Guid.NewGuid())
          Directory.CreateDirectory(tempDir)
       3. Plain DB dump:
            EXEC "VACUUM INTO @path"; @path = tempDir/db/recordum.db
            (SQLite respects the cipher key for read but writes plain to the target.
             Retry up to 3× on SQLITE_BUSY with 100 ms backoff.)
       4. Copy AttachmentsDirectory contents → tempDir/attachments/
       5. Build manifest.json:
            counts via SELECT COUNT(*) on habits / completions / notes / attachments
            plugins via IPluginManager.ListActivatedManifests()
            permissions = new PermissionState(new Dictionary<string, IReadOnlyList<string>>())   // empty in Phase 3
            kind = options.Kind
       6. Stream-zip tempDir → tempDir.zip   (System.IO.Compression, DEFLATE Normal)
       7. AesGcmBackupCipher.EncryptAsync(tempDir.zip → destinationPath, passphrase, ct)
          (writes header + ciphertext + tag in one pass)
       8. Best-effort shred: overwrite tempDir files with zeros, Directory.Delete(tempDir, recursive: true)
       9. INSERT backup_log row
       10. return BackupResult
       11. If options.Kind == Auto: apply retention (delete oldest backup_log rows + files until count ≤ retention).
```

## 9. Restore flow

```
caller (UI)
  └─ RestoreService.PreviewAsync(sourcePath, passphrase, ct)
       1. Open sourcePath, validate magic == "RCBK" and version == 0x01.
       2. tempZip = Path.GetTempFileName() + ".zip"
       3. AesGcmBackupCipher.DecryptAsync(sourcePath → tempZip, passphrase, ct)
          → throw RestoreException("invalid_passphrase") on GCM tag mismatch.
       4. Open tempZip read-only, read manifest.json.
       5. Validate manifest.schema_version major matches current major; if backup major > current
          → RestoreException("incompatible_schema"). Minor mismatch is OK (EF migrations will catch up).
       6. Compute warnings: each plugin in manifest not in IPluginManager.ListActivatedManifests() → "Plugin {id} not available".
       7. Cache tempZip path on the returned RestorePreview (for the subsequent RestoreAsync call).
       8. return RestorePreview.

  └─ RestoreService.RestoreAsync(sourcePath, passphrase, options, ct)
       1. Re-run Preview (idempotent, fresh tempZip — we don't trust a stale handle).
       2. Safety snapshot (unless options.SkipSafetySnapshot):
            BackupService.CreateAsync(BackupsDirectory + "/pre-restore-{ts}.recbak",
                                      autoBackupPassphraseIfPresent ?? passphrase,
                                      new BackupOptions(BackupKind.PreRestore), ct)
          Hard abort the restore on any failure here.
       3. Close DbContext + connection pool (SqliteConnection.ClearAllPools()).
       4. Delete DatabasePath, recursively empty AttachmentsDirectory.
       5. Extract from tempZip:
            db/recordum.db → tempPlainDb
            For each entry under attachments/ → AttachmentsDirectory
       6. Re-encrypt the DB to its destination via the M3.2 cipher infrastructure:
            Open tempPlainDb as plain SQLite (no key), ATTACH @destinationPath KEY '...' AS enc,
            SELECT sqlcipher_export('enc'), DETACH enc. The destination ends up SQLCipher-encrypted
            with the current key from IDbKeyProvider.
            (Edge: on a brand-new machine without db.key yet, ApplicationInitializer's bootstrap has
             already initialized the DPAPI key on first run before restore is reachable from the UI.
             The cipher key always exists by the time RestoreAsync runs.)
       7. Plugin reconciliation: for each manifest plugin not in current activated list →
            RestoreResult.UnavailablePlugins.Add(pluginId)
          Activated core plugins are no-ops (already registered at startup).
       8. Show "Restore complete — Recordum will restart now" dialog → App.Shutdown(0), relaunch wrapper.
       9. On next startup: ApplicationInitializer applies migrations (no-op if same version,
          minor-bump catch-up otherwise), schedulers resume.
```

## 10. Auto-backup scheduler

`BackupSchedulerHost` is a singleton WPF-side service started in `ApplicationInitializer` after migrations and plugin activation. It owns a `System.Threading.PeriodicTimer` ticking every 60 minutes (loose check; we don't need second-precision).

```
tick:
  if !backup.auto.enabled                                   → return
  if AutoBackupKeyPath missing or unreadable (DPAPI fail)   → set backup.auto.enabled=false; emit SystemBackupFailedPayload; return
  passphrase = ProtectedData.Unprotect(File.ReadAllBytes(AutoBackupKeyPath))
  last = parse(backup.auto.last_run_utc) ?? DateTime.MinValue
  if (clock.UtcNow - last) < frequency_days days            → return
  destination = backup.auto.path + "/auto-{yyyyMMdd-HHmm}.recbak"
  await BackupService.CreateAsync(destination, passphrase, new(BackupKind.Auto), ct)
  set backup.auto.last_run_utc = clock.UtcNow
  apply retention
```

**Inert state.** If the user enables auto-backup in settings but does not set a passphrase, no `AutoBackupKeyPath` file exists yet → scheduler skips quietly each tick. The Settings dialog warns prominently when this is the case. Once the user provides a passphrase, the scheduler writes the DPAPI-wrapped blob and runs at the next tick.

**Cleanup on startup.** Orphan temp directories matching `recordum-bk-*` in `Path.GetTempPath()` older than 1 hour are deleted by `BackupSchedulerHost.Initialize()` (mitigates crash-mid-backup leftovers).

## 11. Error handling — deterministic table

| Scenario | Behavior |
|---|---|
| Backup: destination not writable / disk full | `BackupException("destination_not_writable")` → localized dialog; no state changed. |
| Backup: empty passphrase | UI validates first (`CanExecute=false`); service throws `ArgumentException` as a safety net. |
| Backup: DB busy (concurrent write) | `VACUUM INTO` retried 3× × 100 ms; then `BackupException("db_busy_retry_later")`. |
| Backup: crash mid-flight | Temp dir orphaned. Cleaned up at next startup by `BackupSchedulerHost.Initialize()`. No `backup_log` row (insert is the last step). No DB corruption. |
| Restore: invalid magic / version | `RestoreException("invalid_format")` immediately, no decrypt attempted. |
| Restore: wrong passphrase | AES-GCM tag verify fails → `RestoreException("invalid_passphrase")`. Not distinguishable from a tampered file — that's intentional (no oracle). |
| Restore: backup schema_version major > current major | `RestoreException("incompatible_schema")` with the backup's app version surfaced to the user. |
| Restore: backup schema_version minor < current | Proceeds. EF migrations apply the delta on next startup. Tested explicitly. |
| Restore: pre-restore safety snapshot fails | **Hard abort**. We never overwrite live data without a snapshot — unless the user explicitly checked "skip safety snapshot" (not default, requires confirmation). |
| Restore: plugin in manifest not currently activated (e.g. removed core, future sideloaded) | Restore proceeds. `RestoreResult.UnavailablePlugins` surfaced in the post-restore dialog. Provenance rows (`created_by_plugin_id`) stay intact. |
| Auto-backup: DPAPI key missing/corrupt | Scheduler self-disables (`backup.auto.enabled=false`), emits `SystemBackupFailedPayload` on the `IEventBus`. Manual flows are unaffected. |
| Auto-backup: disk space limited | Retention enforced **before** new backup (delete oldest first). If still no space → log + skip + retry next tick. |

  - byte-flip in ciphertext → tag verification fails;
  - byte-flip in header → invalid format detection;
  - version byte > 0x01 → `RestoreException("invalid_format")`.
- `BackupServiceTests` (integration):
  - Round-trip: create on a seeded DB → decrypt + open inner zip → assert `manifest.json` parses, `db/recordum.db` is a valid SQLite plain file, attachment files copied verbatim.

  - `backup_log` row inserted with correct kind/size/path.
  - Retention: 9th Auto backup → 1st auto deleted, file removed from disk.

## 15. Known non-goals (reinforced)

- No cloud sync (Phase 5).
- No incremental / differential backup.
- No selective restore (per-habit, per-date-range).
- No persisted plugin install table or persisted permission decisions in Phase 3 (Phase 7). The backup format already reserves `permissions` for them.
- No WebView2 cache / plugin IndexedDB in the backup (Phase 7).
- No retention-by-age (only retention-by-count). Adding age-based retention later is a one-AppSetting + one-query change.

## 16. Source-of-truth alignment

- **Plugin system design §7.9** (`docs/superpowers/specs/2026-05-13-plugin-system-design.md`): satisfied. Backup includes plugin list (`{plugin_id, version, enabled, sideloaded}`) and permission state placeholder; binaries are not included; restore reconciles against the registry (currently the activated-core registry). Encryption uses the same KDF family as the DB passphrase path (Argon2id 64 MiB / 4 iter / p=2), per §11.
- **CLAUDE.md §6** (schema invariants): new `backup_log` follows naming snake_case, CHECK on enum-like text, explicit `created_at` ISO 8601, explicit indices declared in Fluent.
- **CLAUDE.md §7 milestone 3.10b**: closes this milestone.
- **Roadmap principles**: schema bump v2.6 → v2.7 is additive (no destructive change to existing columns), preserving the "no invasive migrations after Phase 3" promise.
