# Milestone 3.4 — Habit Editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the right-anchored side-pane Habit Editor that creates and edits any `HabitNode` (habit or group) plus its full configuration aggregate (`HabitConfig`, `MetricDefinition[]`, `SegmentDefinition[]`, `Goal`, `Notification[]`, `HabitNodeTag[]`), with progressive disclosure (L1 header always visible, L2 collapsible sections, L3 per-section Advanced toggle) and per-field autosave on blur.

**Architecture:** Composition — one `HabitEditorViewModel` hosts eleven section VMs (`SchedulingSection`, `StreakSection`, `TimerSection`, `MetricsSection`, `ScalesSection`, `GoalSection`, `NotificationsSection`, `TagsSection`, `AiSharingSection`, `DataSourceSection`, `ResetTimeSection`). Each section owns its own validation and persists via existing Core services. Pane visibility driven by new `HomeViewModel.SelectedRow`. Create flow opens a `HabitTemplatePicker` modal that calls a new `IHabitTemplateService.InstantiateAsync`.

**Tech Stack:** C# / .NET 10, WPF + `CommunityToolkit.Mvvm`, EF Core 9 + SQLCipher, xUnit + `FluentAssertions`.

**Spec:** `docs/superpowers/archive/specs/2026-05-20-milestone-3.4-habit-editor-design.md` is authoritative on conflicts with this plan.

```csharp
// src/Recordum.Data/Services/HabitTemplateService.cs
using Microsoft.EntityFrameworkCore;
using Recordum.Core.Abstractions;
using Recordum.Core.Abstractions.Services;
using Recordum.Core.Errors;
using Recordum.Core.Models;

namespace Recordum.Data.Services;

public sealed class HabitTemplateService(
    IDbContextFactory<RecordumDbContext> dbFactory,
    IClock clock,
    IPluginContext plugin,
    IHabitNodeService nodes,
    IHabitConfigService configs) : IHabitTemplateService
{
    public async ValueTask<IReadOnlyList<HabitTemplate>> ListAsync(CancellationToken ct = default)
    {
        await using var db = await dbFactory.CreateDbContextAsync(ct);
        return await db.HabitTemplates.AsNoTracking().OrderBy(t => t.Name).ToListAsync(ct);
    }

    public async ValueTask<Guid> InstantiateAsync(Guid templateId, Guid? parentId, CancellationToken ct = default)
    {
        await using var db = await dbFactory.CreateDbContextAsync(ct);
        var tmpl = await db.HabitTemplates.AsNoTracking().FirstOrDefaultAsync(t => t.Id == templateId, ct)
            ?? throw new HabitTemplateNotFoundException(templateId);

        var node = new HabitNode
        {
            ParentId = parentId,
            NodeType = NodeType.Habit,
            HabitType = tmpl.HabitType,
            Name = tmpl.Name,
            Description = tmpl.Description,
            Color = tmpl.Color ?? "#808080",
            Icon = tmpl.Icon,
        };
        var newId = await nodes.CreateAsync(node, ct);

        await configs.UpsertAsync(newId, cfg =>
        {
            cfg.ScheduleType = tmpl.ScheduleType ?? Recordum.Core.Enums.ScheduleType.Daily;
            cfg.ScheduleDaysJson = tmpl.ScheduleDaysJson;
            cfg.StreakMode = tmpl.StreakMode ?? Recordum.Core.Enums.StreakMode.Consecutive;
            cfg.StreakRecovery = tmpl.StreakRecovery ?? Recordum.Core.Enums.StreakRecovery.None;
            cfg.HasIntegratedTimer = tmpl.HasIntegratedTimer;
            cfg.TimerMode = tmpl.TimerMode;
            cfg.TimerTargetSeconds = tmpl.TimerTargetSeconds;
        }, ct);

        return newId;
    }
}
```

```csharp
    await using var db = await dbFactory.CreateDbContextAsync(ct);
    return await db.HabitNodeTags
        .AsNoTracking()

        .Select(l => l.Tag)

        .ToListAsync(ct);
}

public async ValueTask SetTagsAsync(Guid habitNodeId, IReadOnlyCollection<Guid> tagIds, CancellationToken ct = default)
{
    ArgumentNullException.ThrowIfNull(tagIds);
    await using var db = await dbFactory.CreateDbContextAsync(ct);
    var existing = await db.HabitNodeTags.Where(l => l.HabitNodeId == habitNodeId).ToListAsync(ct);
    db.HabitNodeTags.RemoveRange(existing);
    foreach (var id in tagIds.Distinct())
        db.HabitNodeTags.Add(new HabitNodeTag { HabitNodeId = habitNodeId, TagId = id });
    await db.SaveChangesAsync(ct);
}
```

```csharp
    mutate(goal);
```

```csharp
    public static readonly DependencyProperty IconProperty = DependencyProperty.Register(
        nameof(Icon), typeof(string), typeof(IconPicker),

        nameof(SelectedIconGeometry), typeof(System.Windows.Media.Geometry), typeof(IconPicker), new PropertyMetadata(null));
```

## Phase D — Sections

The pattern is identical for every section:
1. Section VM extends `SectionViewModelBase`. Constructor takes its service dependency.
2. `LoadAsync(HabitNode, HabitConfig?)` populates observable fields from the entity.
3. Each `[ObservableProperty]` has an `OnXxxChanged` partial that validates locally then calls `ApplyAsync(() => service.UpdateXxxAsync(...))`.
4. `IsApplicable(NodeType, HabitType?)` returns the section's row from the visibility matrix (spec §6).
5. Each section has a paired XAML `UserControl`. Layout: expander with the section title; collapsed by default. Inside: field rows + per-field error tooltip on Status==Error. Bottom: small "Advanced" ToggleButton when L3 fields exist; bound to `ShowAdvanced`.

For all eleven sections below, follow this contract. Each task lists the section-specific fields, services, validation, and view content.
