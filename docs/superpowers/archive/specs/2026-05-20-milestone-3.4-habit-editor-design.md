# Milestone 3.4 — Habit Editor Design

> **Status:** Approved 2026-05-20. Authoritative for the M3.4 implementation plan. Conflicts with `Recordum_ProductSpec_v2.docx` are deliberate scope choices and called out in §10.

## 1. Goal

Ship the editor that lets users **create and edit** any `HabitNode` (habit or group) plus its associated configuration aggregate (`HabitConfig`, `MetricDefinition[]`, `SegmentDefinition[]`, `Goal`, `Notification[]`, `HabitNodeTag[]`). Editor lives as a **right-anchored side pane** in `MainWindow`, opens via single-click on a Home row, and persists every field on blur with optimistic UI + snap-back on validation failure.

Progressive disclosure follows CLAUDE.md §9: L1 always visible, L2 collapsible sections (default collapsed), L3 "Advanced" toggle per section.

## 2. Scope

**In scope:**
- Create flow: `+ New` button on Home top bar opens a modal **template picker** (8 seeded `HabitTemplate` + Blank habit + Blank group), then opens the pane on the newly created node.
- Edit flow: single-click any row in Home → pane opens for that node. Selection state and the pane visibility are unified (`HomeViewModel.SelectedRow`).
- Same editor for `NodeType.Group` and all five `HabitType` values, with **conditional section visibility** (matrix in §6).
- Per-field autosave on blur via existing service interfaces.
- Section visibility, L3 "Advanced" reveal per section, validation with snap-back, footer status (`Saved` / `Saving…` / `Couldn't save: …`).
- E2E unit + integration tests covering every section VM, the section visibility matrix, the template picker, and the editor↔Home wiring.

**Out of scope (deferred — explicit):**
- Bulk edit / multi-select edits.
- Inline notes editor (rich Markdown) → M3.6.
- Drag-to-reorder metrics / segments — basic add/remove only in 3.4.
- Color picker beyond a 12-swatch palette + free hex input.
- Icon picker beyond the Lucide set shipped in M3.3.

## 3. Presentation

| Aspect | Decision |
|---|---|
| Container | Right-anchored `Border` overlay inside `MainWindow.Grid`, on top of `HomeView` |
| Default width | 480 px, resizable via vertical `GridSplitter` on the left edge; width persisted in `AppSetting` `editor.pane_width` |
| Open trigger | Single-click anywhere in a row (but not on the rename TextBox / context-menu chrome) calls `HomeViewModel.SelectRow(row)`. Plan adds `MouseLeftButtonUp` handler to both `HabitRowTemplate.xaml` and `GroupRowTemplate.xaml` (M3.3 row templates don't have this wired yet). Right-click context menu still opens via `Grid.ContextMenu`. |
| Close | Header `×` button OR clicking outside the pane onto the tree → `SelectedRow = null` |
| Empty state | Hidden when `SelectedRow == null` (`Visibility=Collapsed`) |
| Header content | Icon swatch · 12-color palette + hex input · Name TextBox · NodeType+HabitType combos · `×` close |
| Footer content | `EditorStatus` text (`Idle` / `Saving` / `Saved at HH:mm:ss` / `Error: <msg>`) · "Move to Trash" link |

## 4. Architecture — VM topology

Composition: one `HabitEditorViewModel` (top) hosts ten section VMs:

```
HabitEditorViewModel
 ├── Header L1 (inline; bound to HabitNode fields)
 ├── SchedulingSectionViewModel
 ├── StreakSectionViewModel
 ├── TimerSectionViewModel
 ├── MetricsSectionViewModel
 ├── ScalesSectionViewModel
 ├── GoalSectionViewModel
 ├── NotificationsSectionViewModel
 ├── TagsSectionViewModel
 ├── AiSharingSectionViewModel
 ├── DataSourceSectionViewModel
 └── ResetTimeSectionViewModel
```

Each section VM:
- Owns its own visible fields + (`ShowAdvanced` bool when L3 fields exist).
- Computes `IsApplicable(NodeType, HabitType)` (drives `Visibility` of the corresponding `*Section.xaml`).
- Exposes `SaveStatus : EditorStatus` (lifted into the editor's `OverallStatus`).
- Hosts per-field validators (synchronous; rules per `§7`).
- Calls into one Core service per concern (see §5).

`HabitEditorViewModel`:
- Receives `HomeRowViewModel? Row` from `HomeViewModel.SelectedRow`. Lifecycle: a single `HabitEditorViewModel` instance lives for the pane (registered Transient and resolved once by `MainWindowViewModel`); when `Row` changes, the editor calls `LoadAsync(row)` which rebuilds all section VMs from the freshly-fetched aggregate (`IHabitNodeService.GetAsync` + `IHabitConfigService.GetAsync` + …). Disposing an old section VM is just letting it be GC'd; no native resources held.
- Owns `EditorStatus OverallStatus` = max severity across sections.
- Disposes / rebuilds section VMs when `Row` changes.

## 5. Service surface

Existing services suffice; some need a thin contract extension:

| Concern | Service | New method(s) |
|---|---|---|
| HabitNode L1 fields | `IHabitNodeService` (existing) | reuse `UpdateAsync(id, mutate)` |
| HabitConfig | `IHabitConfigService` (existing) | `UpsertAsync(habitNodeId, mutate)` — create if missing else update; snapshots via interceptor |
| Goal (1 per habit/group, latest active) | `IGoalService` (existing) | `UpsertActiveGoalAsync(habitNodeId, mutate)` — closes previous active, opens new |
| Notification[] | `INotificationService` (existing) | `ListAsync`, `CreateAsync`, `UpdateAsync`, `DeleteAsync` |
| Metric[] | `IMetricDefinitionService` (existing) | `ListAsync(habitNodeId)`, `AddAsync`, `UpdateAsync`, `RemoveAsync` |
| Segment[] (counter session) | new `ISegmentService` | `ListAsync`, `AddAsync`, `UpdateAsync`, `RemoveAsync`, `ReorderAsync` |
| Tags (M:N) | `ITagService` (existing) | `ListAllAsync`, `GetTagsForHabitAsync(habitNodeId)`, `SetTagsAsync(habitNodeId, ids)` |
| Template instantiation | `IHabitTemplateService` (existing) | `InstantiateAsync(templateId, parentId?)` — clones the template, returns the new `HabitNode.Id` |
| Pane width persistence | `IAppSettingService` (existing) | reuse |

**Audit of existing services** is required at plan-writing time — some methods listed above may already exist under different names. The plan tasks verify and adapt.

## 7. Validation rules

All synchronous; failure = field reverts to previous value + footer `Error: <msg>`.

| Field | Rule |
|---|---|
| `Name` | non-empty after trim, max 200 chars |
| `Color` | matches `^#[0-9A-Fa-f]{6}$` |
| `Description` | nullable, max 2000 chars |
| `ScheduleType=Weekly` | `ScheduleDaysJson` must parse to non-empty array of weekday strings |
| `ScheduleType=EveryXDays` | `ScheduleEveryXDays >= 1` |
| `ScheduleType=Monthly` | `ScheduleMonthlyDaysJson` parses to non-empty array of ints 1..31 |
| `StreakRecovery=Tolerance` | `StreakToleranceMinutes > 0 && <= 1440` |
| `TimerMode=Session` | `SegmentDefinitions.Count >= 1` AND each has positive `DurationSeconds` |
| `TimerTargetSeconds` | `> 0` when `HasIntegratedTimer` |
| `Goal.TargetValue` | `> 0` |
| `Goal.Deadline` | `> CurrentDate` (via `IClock`) |
| Notification | at most one row per (`Kind`, `Time`) tuple |
| Metric definition | `Name` non-empty, max one of `IsPrimary=true` per habit |

| `BootstrapSmokeTests` | E2E: bootstrap → pick template → edit a field → assert persisted in DB |

Target: **all new tests use existing test fixture patterns** (`DbFixture`, fake services). Build clean, zero warnings.

## 9. Acceptance criteria (mirror of CLAUDE.md §7 row 3.4)

1. **Progressive disclosure 3 levels**: L1 visible always, L2 sections collapse/expand, L3 hidden behind "Advanced" per section.
2. **All five habit types editable**: action / counter (+ session) / resistance / journal / state.
3. **Groups editable in the same editor** with conditional sections.
4. **Template instantiation works**: picking a seeded `HabitTemplate` creates a habit prefilled from it.
5. **Autosave with snap-back**: every field commits on blur; validation failure reverts the field; service exception reverts + footer error.
6. **No hardcoded strings** — every label/error in `Strings.resx` (en) + `Strings.it.resx`.
7. **All sections testable in isolation** — section VMs unit-testable without WPF runtime.
8. **Build clean, all tests green** before merge.

## 10. Known limits / deferred decisions

- **Metric/Segment ordering**: in-pane reorder via drag deferred. Add/remove + last-write-wins position via creation order is enough for 3.4. Reorder is a small follow-up (3.4.1 or fold into 3.5).
- **Color picker richness**: 12-swatch palette + hex input. No gradients, no eyedropper. Sufficient per design brief "colore = identificatore, mai decorazione".
- **Icon picker**: paged grid over the existing Lucide icons resource (Icons.xaml). No file-upload of custom SVGs in 3.4 — that's a plugin territory (M3.7).
- **Confirm-on-close-with-unsaved-changes**: not needed because every field is autosaved. The pane has no Save button.
- **Multi-edit**: explicitly deferred; not blocking 3.5+.
- **Per-section dirty state**: not tracked separately — each field is independently committed. Section "is currently saving" indicator is enough.
