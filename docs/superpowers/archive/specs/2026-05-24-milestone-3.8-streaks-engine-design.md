# Milestone 3.8 — Streaks Engine — Design

**Date**: 2026-05-24
**Status**: Approved, ready for plan
**Predecessor**: M3.7 (Habit Detail Screen — introduced `IStreakAggregator` + `NaiveDailyStreakAggregator`)
**Successor**: M3.9 (Custom Charts)

## 1. Scope

Replace `NaiveDailyStreakAggregator` with a complete `SchedulingAwareStreakAggregator` that respects every axis of streak semantics defined in the product spec: `ScheduleType` × `StreakMode` × `StreakRecovery` × `StreakPause` × `HabitConfigHistory` (per-day config resolution) × `IResetTimeResolver` (day-boundary cascade). Introduce `IResetTimeResolver` (technical debt outstanding since M3.3). Add one schema column (`streak_broken_at`) to support `StreakRecovery=Manual`.

**Out-of-scope** (deferred):
- UI for `StreakPause` CRUD (service already exists from M3.5).
- UI button for `MarkBrokenAsync` (service shipped headless).
- Streak-aware notifications.
- Materialized `streak_run_cache` table (only if perf budgets fail).
- Plugin extension-point for streak engines (M7).

## 2. Architecture

```
                    ┌──────────────────────────────────────────────┐
                    │   IStreakAggregator (Core, signature stable) │
                    │   GetHistoryAsync(habitId, from, to)         │
                    └──────────────────────────────────────────────┘
                                       ▲
                       (DI: replaces NaiveDailyStreakAggregator)
                                       │
        ┌──────────────────────────────────────────────────────────────────┐
        │  Recordum.Data.Services.Aggregators.SchedulingAwareStreakAggregator │
        │  - Single-pass walker [from..to]                                  │
        │  - Builds HabitConfigTimeline once per query                      │
        │  - Per day delegates to injected evaluators/policy                │
        └──────────────────────────────────────────────────────────────────┘
                      │             │              │            │
                      ▼             ▼              ▼            ▼
        IScheduleEvaluator   IStreakModeEvaluator   IStreakRecoveryPolicy  IResetTimeResolver
        (1 impl,             (4 impls, keyed         (4 impls, keyed       (1 impl, walks
         internal switch     by StreakMode)          by StreakRecovery)    parent chain)
         on ScheduleType)

        IStreakPauseService.ListByHabitAsync     → pre-fetch pauses overlapping [from..to]
        IHabitConfigService + history            → pre-fetch full timeline
        ICompletionService.GetHeatmapAsync       → daily completion-count map (live + with-retroactive)
        ICompletionService.GetDailySumAsync      → primary-metric daily value map (when relevant)
```

### Responsibility boundaries

- `IScheduleEvaluator.IsScheduled(date, ScheduledRules)` → `bool`
- `IStreakModeEvaluator.Evaluate(DayContext)` → `DayVerdict { Counts | Misses | Neutral }`
- `IStreakRecoveryPolicy.TryAbsorb(RecoveryContext)` → `bool`
- `IResetTimeResolver.GetEffectiveResetTimeAsync(habitNodeId)` → `TimeOnly`

The aggregator orchestrates: ask `IsScheduled`, check pauses, fetch `completedToday`, delegate to mode evaluator, on `Misses` consult recovery policy.

**Stateless** except for per-query in-memory caches. No new tables; one new column on `habit_config`.

## 4. Data flow + per-day algorithm

### 4.1 Sequence diagram

```
StreakSummaryVM / StreakTimelineVM
        │
        ▼
IStreakAggregator.GetHistoryAsync(habitId, from, to)
        │
        ├─► [1] Pre-fetch (1 time per query):
        │     • IResetTimeResolver.GetEffectiveResetTimeAsync(habitId)
        │     • IHabitConfigService.GetAsync(habitId) + history list → HabitConfigTimeline
        │     • IStreakPauseService.ListByHabitAsync(habitId)        → pauses (filter overlap [from..to])
        │     • ICompletionService.GetHeatmapAsync(habitId, from, to) twice:
        │         - excluding IsRetroactive       → dailyCountLive
        │         - including IsRetroactive       → dailyCountAll
        │     • If habit has primary metric numeric:
        │         GetDailySumAsync(habitId, metric, from, to)        → dailyValueMap
        │
        ├─► [2] Walker from `from` to `to` (DateOnly by DateOnly):
        │     for each day D:
        │       cfg          := timeline.ResolveFor(D)
        │       rules        := ScheduledRules(cfg, habit.CreatedAt.LocalDate)
        │       isScheduled  := IScheduleEvaluator.IsScheduled(D, rules)
        │       isPaused     := pauses.Any(p => D in [p.PauseFrom..p.PauseTo])
        │       completedCnt := (cfg.StreakRecovery == Retroactive)
        │                         ? dailyCountAll[D] : dailyCountLive[D]
        │       completedVal := dailyValueMap?[D] ?? 0
        │       weekState    := computeWeekStateIfWeekly(D, cfg)
        │
        │       modeEval     := keyedEvaluators[cfg.StreakMode]
        │       verdict      := modeEval.Evaluate(new DayContext(...))
        │
        │       (state machine — see 4.2)
        │
        └─► [3] Emit List<StreakRun> with last-run flagged IsCurrent if End ∈ {today, today-1}.
```

### 4.2 Loop body (state machine)

```
state = { runStart: null, runEnd: null, length: 0, recoveriesUsed: 0,
          missesInWindow: 0, lastRecoveryWindowAnchor: null,
          prevMode: null }

for each day D:
    if verdict == Neutral:                         → skip (non-scheduled, no impact)
        continue

    if isPaused:                                   → skip but extend runEnd to D
        if runStart != null: runEnd = D
        continue

    if verdict == Counts:
        if runStart == null: runStart = D
        runEnd = D
        length += 1
        if D >= lastRecoveryWindowAnchor + 7:
            missesInWindow = 0
            lastRecoveryWindowAnchor = D
        prevMode = cfg.StreakMode
        continue

    if verdict == Misses:
        # Manual handled first:
        if cfg.StreakRecovery == Manual:
            if cfg.StreakBrokenAt != null && DateOnly.FromDateTime(cfg.StreakBrokenAt.Value) <= D:
                closeRun(reason: Manual)
            # otherwise run stays open (Manual + no trigger)
            continue

        absorbed = recoveryPolicy.TryAbsorb(
            new RecoveryContext(D, missesInWindow, cfg.StreakBrokenAt, runStart))
        if absorbed:
            missesInWindow += 1
            recoveriesUsed += 1
        else:
            closeRun(reason: Missed)
        continue

# after loop:
if runStart != null:
    emit StreakRun(runStart, runEnd, length,
                   IsCurrent = (runEnd >= today - 1),
                   RecoveriesUsed = recoveriesUsed,
                   BreakReason = null)
```

`closeRun(reason)` emits a `StreakRun` and resets `runStart/runEnd/length/recoveriesUsed/missesInWindow` to initial.

### 4.3 StreakMode semantics

| Mode | Verdict logic |
|---|---|
| **Daily** | `isScheduled && completedCnt==0` → `Misses`; `isScheduled && completedCnt>0` → `Counts`; else `Neutral`. |
| **Weekly** | `Counts` if D is the last scheduled day of ISO week AND `weekState.CompletionsSoFar >= weekState.RequiredCompletions`. `Misses` if last day of week AND target unmet. `Neutral` otherwise. `runEnd` granularity stays day-level (Sunday of the satisfied week). `length` counts weeks. |
| **Occurrences** | `Counts` if `completedCnt > 0`; never `Misses` (inactivity does not break — only Manual or `closeRun` via config issues does). `length` = consecutive completion-days from last break. |
| **Both** | Combines Daily + Weekly: `Misses` if either Daily or Weekly evaluator says `Misses` (and not absorbed). `Counts` requires both `Counts`. |

### 4.4 Pause handling

- Pauses absorb both `Counts` and `Misses` → "Neutral with extend": extend `runEnd` but do not increment `length`, do not consume recovery.
- Overlapping pauses: `Any()` predicate is union-implicit; service does not deduplicate.
- Pause beyond `today` → extends `runEnd` only up to `min(PauseTo, walkerEnd)`.

### 4.5 HabitConfigTimeline — per-day resolution

```csharp
internal sealed class HabitConfigTimeline {
    public HabitConfig ResolveFor(DateOnly date) {
        // 1. Find HabitConfigHistory with ValidFrom.AsDate ≤ date < ValidUntil.AsDate.
        // 2. Otherwise the current HabitConfig represents [lastUpdate..∞).
        // 3. If date < earliest known ValidFrom → current (only existing config).
    }
}
```

**Interceptor recap (M3.2)**: when `HabitConfig` is modified, the interceptor snapshots **original** values into `HabitConfigHistory` with `ValidFrom = OriginalUpdatedAt`, `ValidUntil = nowUtc`. The live `HabitConfig` represents the segment `[lastUpdate..∞)`.

### 4.5b Recovery policy behavior matrix

| Policy | `TryAbsorb` returns | Rationale |
|---|---|---|
| `None` | `false` always | Any miss breaks the run immediately. |
| `GraceDay` | `true` if `MissesAbsorbedInWindow < 1` in the rolling 7-day window | 1 miss tolerated per window. |
| `Manual` | (not consulted — short-circuited in §4.2 before reaching the policy) | Run only breaks via explicit `StreakBrokenAt`. |
| `Retroactive` | `false` always | The retroactive effect is achieved by switching the data source (dailyCountAll vs dailyCountLive); no absorption logic. |

### 4.6 Retroactive completion

The `IsRetroactive` flag on `Completion` is already excluded from `HourlyHistogram`. For the streak engine:

- If `cfg.StreakRecovery == Retroactive` for day D → the engine reads `dailyCountAll[D]` (includes retroactive backfills).
- Otherwise it reads `dailyCountLive[D]` (excludes retroactive).
- This is per-day, so changing the policy mid-history works correctly.

## 5. Error handling + edge cases

### 5.1 Input validation

| Input | Handling |
|---|---|
| `from > to` | Throw `ArgumentException("from must be <= to")`. |
| `habitNodeId` unknown | Aggregator returns `Array.Empty<StreakRun>()`. |
| `habitNodeId` is a `Group` | Returns `Array.Empty<StreakRun>()` silently. |
| Range > 10 years | No cap; budget applies per year (§5.4). |
| `habit.CreatedAt > from` | Days before `CreatedAt` are `Neutral` (`IScheduleEvaluator` returns false). |
| `HabitConfig` missing | Throw `InvalidOperationException("Habit has no config")`. |

### 5.2 Boundary edge cases

| Case | Behavior |
|---|---|
| Habit created today, 1 completion | Run length=1, IsCurrent=true. |
| Empty history | `Array.Empty<StreakRun>()`. |
| Active run extends past `to` | Last run: `End=to`, `IsCurrent` reflects "run reaches `to` and `to` is today/yesterday". |
| `from=today-89` but run started 100d ago | Run truncated to `Start=from`. `StreakSummaryViewModel` compensates with a separate full-range call for "Longest". |
| `StreakMode` change mid-run | Run continues; new evaluator applies from the change-day onward. Explicit `MarkBroken` is the user-driven path. |
| `StreakBrokenAt` set after run already closed | Marker is a current-segment flag (column not versioned). Older closed runs unaffected. |
| Pause with `PauseTo > today` | Extends `runEnd` to `min(PauseTo, walkerEnd)`. |
| Overlapping pauses | Union-merged implicitly. |
| `WeeklyTarget` changes mid-week | Per-day resolution: end-of-week day uses that day's `cfg`. |
| All-Neutral history (rare config) | Run never starts → empty result. |

### 5.3 Internal failure modes

- `HabitConfigTimeline.ResolveFor` finds no match → `InvalidOperationException`, logged via `LoggerMessage`, query returns empty.
- Malformed JSON in `DaysJson` / `MonthlyDaysJson` → `IScheduleEvaluator` logs warning once and treats day as not scheduled.
- Cycle in parent chain (defensive against post-M3.5 invariants) → depth cap 32; fallback to `AppSetting.daily_reset_time`.

### 5.4 Cancellation, concurrency, migrations

- Walker checks `ct.ThrowIfCancellationRequested()` every 365 days. Pre-fetch passes `ct` to all services.
- Aggregator is stateless beyond per-query data — safe for concurrent calls.
- `IStreakService.MarkBrokenAsync` reuses `IHabitConfigService.UpsertAsync` → inherits M3.2 concurrency (last-write-wins via `UpdatedAtMs`).
- `StreakBrokenAtV26` migration: additive `ADD COLUMN`, NULL backfill, bump `schema_version`.

## 10. Design decisions summary

1. **Approach A** — Single-pass walker + strategy classes (rejected: monolithic FSM, materialized cache).
2. **Minimal schema delta** — `streak_broken_at` only (v2.6).
3. **Full matrix**: 4 mode × 4 recovery × 6 schedule × pause × per-day config.
4. **`IResetTimeResolver` introduced here** (pre-existing CLAUDE.md debt from M3.3).
5. **`StreakRun` extended non-breaking** with `IsCurrent`/`RecoveriesUsed`/`BreakReason?`.
6. **Test strategy**: Theory matrix + 13 narrative cases + Resolver + Service + Migration + Perf trait.
7. **Headless**: no new UI; banner removed.
