# Milestone 3.6 — Journal Editor + Notes Design

> **Status:** Approved 2026-05-22. Authoritative for the M3.6 implementation plan. Conflicts with `Recordum_ProductSpec_v2.docx` are deliberate scope choices and called out in §10.

## 1. Goal

Replace the plain `TextBox` shipped in M3.5's `JournalQuickAddViewModel` with a **WebView2 + Toast UI markdown editor**, and ship full CRUD for the existing `Note` entity (per-habit-node persistent markdown notes, distinct from `Completion.Notes`). `HabitScreen` gains a **tab switcher** (Completion | Notes) so notes are addressable without leaving the habit's screen. The streak engine, AI insight, attachments, and app-lock remain out of scope.

## 2. Scope

**In scope:**
- New `MarkdownEditorControl` (WPF UserControl) wrapping a single WebView2 instance + Toast UI Editor bundle (vendored, no CDN). Lazy-init on first `Loaded`; one instance per binding site.
- Journal `QuickAdd` panel: the existing `TextBox` for `Notes` is replaced by `MarkdownEditorControl` inline (~280 px height). Save semantics from M3.5 unchanged (writes to `Completion.Notes`).
- `HabitScreen` gains a `TabControl` with two tabs: **Completion** (M3.5 surfaces unchanged) and **Notes** (master-detail).
- `INoteService` fleshed out: `CreateAsync / UpdateAsync / DeleteAsync / GetAsync / ListByHabitAsync`. Publishes `NoteCreated / NoteUpdated / NoteDeleted` via `IEventBus`.
- New `NotesViewModel` + `NoteRowViewModel`: list + master-detail editor; `New / Save / Delete` commands; subscribes to `IEventBus` for cross-screen consistency.
- `Strings.resx` (en + it) for every new user-facing label, including a localized fatal dialog if the WebView2 Runtime is missing.
- `FakeNoteService` fixture for WPF tests.

**Out of scope (deferred, explicit):**
- **Attachments** (paste/drag images into the editor, persist to `Attachment` rows + encrypted file storage) → M3.7. The Toast UI image button is hidden from the toolbar.
- **`Note.IsSensitive` lock** (hide behind PIN/passphrase) → app-lock milestone. Flag is persisted but the UI does not yet toggle or honour it.
- **Full-text search inside note bodies** → search milestone.
- **Export notes** (markdown / PDF) → M3.10.
- **Markdown editing of `Completion.Notes` for non-Journal habits** (Counter / Resistance / State edit dialog) → stays plain `TextBox`. Only the Journal QuickAdd uses the markdown editor; the Notes tab edits `Note` rows.
- **Bulk note operations** (multi-select delete, reorder).
- **AI sharing toggle on notes** → AI is whole-app concern (Phase 8).

### 3.3 Notes tab content

```
┌─ Notes tab (master-detail, full HabitScreen height) ──────────────┐
│ ┌─ Left: notes list (~180 px) ┐ ┌─ Right: editor ───────────────┐ │
│ │ [+ New note]                │ │                                │ │
│ │ ─────────────────────────── │ │ ┌─ Toast UI ────────────────┐ │ │
│ │ ▸ 2026-05-22 10:42          │ │ │ toolbar                   │ │ │
│ │   "Switched to morning runs"│ │ ├───────────────────────────┤ │ │
│ │ ─────────────────────────── │ │ │                           │ │ │
│ │   2026-05-18 21:03          │ │ │  ## Switched...           │ │ │
│ │   "Plan: 5×1km intervals…" │ │ │  ...                      │ │ │
│ │ ─────────────────────────── │ │ │  (full editor)            │ │ │
│ │   2026-04-30 08:15          │ │ │                           │ │ │
│ │   "Started using HRV"       │ │ └───────────────────────────┘ │ │
│ │                              │ │ [Save]  [Delete]              │ │
│ │  (scroll if many)            │ │                                │ │
│ └──────────────────────────────┘ └────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────┘
```

- Each row: `UpdatedAt` (formatted `yyyy-MM-dd HH:mm`) + first non-empty line of `BodyMd` truncated to ~40 chars as summary (or `(untitled)` if body empty). Selection highlight via 4 px accent bar on the left (mirrors Home rows from M3.3).
- `+ New note` creates a `Note` with `BodyMd = ""`, persists immediately, selects it, focuses the editor. The list updates from the `NoteCreated` event.
- Editor binds `Markdown` to `NotesViewModel.SelectedNote.BodyMd` (TwoWay). **Save is explicit**, not autosave — markdown editing has too many half-typed intermediate states to commit on every keystroke (departure from the per-field autosave used in `HabitEditorViewModel`). The user must click `Save` (or `Ctrl+S` keybinding).
- `Save` button is disabled when the editor content equals the persisted `BodyMd` (dirty-state tracking).
- `Delete` shows inline confirm (`Delete this note?` + `[Yes]` `[Cancel]` swap), then `DeleteAsync`, removes from list, selects the first remaining (or none).
- Empty state when `Notes.Count == 0`: centered `"No notes yet."` + `"Click + to write one."` — both localized.
- Ordering: `UpdatedAtMs DESC`. No manual reorder, no pin.

### 3.4 WebView2 Runtime missing

If `CoreWebView2Environment.CreateAsync` fails at app startup (WebView2 Runtime not installed):
- `ApplicationInitializer` logs the failure but does **not** crash the app.
- HabitScreen's Journal QuickAdd shows a fallback: the M3.5 plain `TextBox`.
- Notes tab is **disabled** (greyed out, tooltip `Editor.WebView2.NotAvailable.Body`).
- A non-blocking banner appears at the top of HabitScreen: `Editor.WebView2.NotAvailable.Body` with a link to the Microsoft installer page (no auto-install).

This degraded mode keeps the app usable for users on Windows 10 without WebView2 Runtime.

### 4.3 `MarkdownEditorControl` contract

```csharp
public partial class MarkdownEditorControl : UserControl
{
    public static readonly DependencyProperty MarkdownProperty =
        DependencyProperty.Register(nameof(Markdown), typeof(string),
            typeof(MarkdownEditorControl),
            new FrameworkPropertyMetadata("",
                FrameworkPropertyMetadataOptions.BindsTwoWayByDefault,
                OnMarkdownPropertyChanged));
    public string Markdown { get; set; }

    public static readonly DependencyProperty IsReadOnlyProperty = ...;
    public bool IsReadOnly { get; set; }

    public static readonly DependencyProperty PlaceholderProperty = ...;
    public string Placeholder { get; set; }
}
```

**Lifecycle:**
1. `Loaded` event → `EnsureCoreWebView2Async(env)` where `env` is a process-wide singleton `CoreWebView2Environment` (resolved from DI).
2. After init, navigate to `https://recordum.local/EditorAssets/editor.html` (via `SetVirtualHostNameToFolderMapping` pointing at the `EditorAssets` content directory shipped next to the .exe).
3. JS bridge:
   - **JS → .NET**: Toast UI `editor.on('change', ...)` posts `{ type: 'change', md: '<...>' }` via `window.chrome.webview.postMessage`. Control receives via `CoreWebView2.WebMessageReceived`, debounced 50 ms, and sets `Markdown` DP (TwoWay).
   - **.NET → JS**: `OnMarkdownPropertyChanged` posts `{ type: 'setContent', md: value }` via `CoreWebView2.PostWebMessageAsString` — JS calls `editor.setMarkdown(md)` only when the incoming value differs from the current editor content (avoids ping-pong).
4. `Unloaded` event → `CoreWebView2 = null`, but the underlying `WebView2` is **disposed** only when the UserControl is removed from the visual tree permanently (`HabitScreenViewModel.Dispose` triggers a `Dispose()` on the control via `Loaded`/`Unloaded`).

### 4.4 `INoteService` contract

```csharp
public interface INoteService
{
    ValueTask<Guid> CreateAsync(Note draft, CancellationToken ct = default);
    ValueTask UpdateAsync(Guid id, Action<Note> mutate, CancellationToken ct = default);
    ValueTask DeleteAsync(Guid id, CancellationToken ct = default);
    ValueTask<Note?> GetAsync(Guid id, CancellationToken ct = default);
    ValueTask<IReadOnlyList<Note>> ListByHabitAsync(Guid habitNodeId, CancellationToken ct = default);
}
```

- `CreateAsync`: assigns `Id`, `CreatedAt` (from `IClock`), `UpdatedAtMs`. Stamps `CreatedByPluginId` via the existing `TimestampInterceptor`. Returns the new id. Publishes `NoteCreatedPayload(Id, HabitNodeId)`.
- `UpdateAsync`: load + mutate + save. Publishes `NoteUpdatedPayload` only when row exists.
- `DeleteAsync`: hard delete (the `notes` table has no `DeletedAt` — only `HabitNode` has soft-delete; cascading delete on HabitNode hard-deletes the note rows).
- `ListByHabitAsync`: ordered by `UpdatedAtMs DESC`, no take. Notes per habit are expected to be small (10s–100s).

### 4.5 `NotesViewModel`

```csharp
public sealed partial class NotesViewModel : ObservableObject, IDisposable
{
    public ObservableCollection<NoteRowViewModel> Notes { get; }
    [ObservableProperty] private NoteRowViewModel? _selectedNote;
    [ObservableProperty] private string _editorMarkdown = "";  // editor binding target
    [ObservableProperty] private bool _isConfirmingDelete;
    public bool IsDirty { get => ...; }                       // editorMarkdown != selectedNote.BodyMd

    [RelayCommand] private Task NewAsync();
    [RelayCommand(CanExecute = nameof(CanSave))] private Task SaveAsync();
    [RelayCommand] private void RequestDelete();              // toggles IsConfirmingDelete
    [RelayCommand] private Task ConfirmDeleteAsync();
    [RelayCommand] private void CancelDelete();

    public Task LoadAsync(Guid habitNodeId, CancellationToken ct);
}
```

**Selection change:**
- When `SelectedNote` changes, unsaved edits in `EditorMarkdown` are **silently discarded**. Rationale: a "Save unsaved changes?" prompt fragments the flow; matches M3.5's explicit-Save decision (no autosave on free-form text). Users learn to click Save. If user feedback requires it, a confirm prompt can be added in M3.6.1 without schema change.
- When a `Note` is selected, `EditorMarkdown` is set to the row's `BodyMd`; the editor's TwoWay binding pushes edits back into `EditorMarkdown` (NOT into `Note.BodyMd` directly until Save).

**Event bus integration:**
- Subscribes to `NoteCreated/Updated/Deleted` for the current `_habitNodeId`. On match, refreshes the list (re-fetch via `INoteService.ListByHabitAsync`) and preserves `SelectedNote.Id` if still present.

### 4.6 DI

```csharp
services.AddScoped<INoteService, NoteService>();
services.AddTransient<NotesViewModel>();
services.AddSingleton<CoreWebView2Environment>(_ => CoreWebView2Environment.CreateAsync().Result);
```

The WebView2 environment is process-wide singleton (Toast UI bundle path resolved once). Created eagerly in `ApplicationInitializer.InitializeAsync` so the missing-runtime case is caught at startup. If creation fails, registered as `null` and the `IWebView2Availability.IsAvailable` flag is false; the markdown editor control falls back as per §3.4.

## 5. Data flow

### 5.1 Save a journal entry (Journal QuickAdd)

```
User types in editor
  → JS 'change' event → WebMessageReceived → Markdown DP changes
  → JournalQuickAddViewModel.Notes = <md>           (TwoWay)
User clicks Save
  → JournalQuickAddViewModel.SaveAsync
  → CompletionService.RecordAsync(Completion { Notes = md, ... })
  → CompletionRecordedPayload published
  → HabitScreenViewModel.OnCompletionEvent → Heatmap + CompletionList reload
```

### 5.2 Create a note (Notes tab)

```
User clicks "+ New note"
  → NotesViewModel.NewAsync
  → INoteService.CreateAsync(new Note { HabitNodeId = _habitNodeId, BodyMd = "" })
  → NoteCreatedPayload published
  → NotesViewModel.OnNoteEvent → re-fetch list, select the new row
  → EditorMarkdown = ""    (editor empty)
```

### 5.3 Save an existing note

```
User edits in editor
  → editor → EditorMarkdown (TwoWay)
  → IsDirty = true → SaveCommand becomes enabled
User clicks Save (or Ctrl+S)
  → NotesViewModel.SaveAsync
  → INoteService.UpdateAsync(SelectedNote.Id, n => n.BodyMd = EditorMarkdown)
  → NoteUpdatedPayload published
  → list summary updates via re-fetch; selection preserved
```

### 5.4 Delete a note

```
User clicks Delete
  → IsConfirmingDelete = true (UI swap to inline confirm)
User clicks Yes
  → NotesViewModel.ConfirmDeleteAsync
  → INoteService.DeleteAsync(SelectedNote.Id)
  → NoteDeletedPayload published
  → list re-fetch; select first remaining or none
  → EditorMarkdown = ""
```

## 10. Risks

- **WebView2 lifecycle in WPF**: WebView2 inside a `DataTemplate` (Journal QuickAdd) may be created/destroyed when DataContext changes. The Toast UI editor's `change` event firing during teardown can post to a disposed control. Mitigation: track `_isDisposed` in `MarkdownEditorControl`, drop late messages.
- **Bundle size**: Toast UI minified is ~1 MB. Acceptable for a desktop app; ships with the exe. CI artefact size grows but stays under any reasonable threshold.
- **Pack URI vs SetVirtualHostNameToFolderMapping**: `pack://` doesn't work for WebView2's Source. We use `SetVirtualHostNameToFolderMapping` pointing at `EditorAssets/` next to the .exe (`AppContext.BaseDirectory`). Tests that resolve the path must use the same logic.
- **Save vs autosave inconsistency** with the rest of M3.4 (Habit Editor uses per-field autosave): documented in §3.3 — markdown editing is "in flight" by nature; autosave would mean noisy events. The explicit Save button matches expected UX (Notion, Obsidian, Bear). Codebase invariant deviation, called out.
- **Two WebView2 instances per HabitScreen** (one in Journal QuickAdd, one in Notes tab): ~60-90 MB RAM. Acceptable. If perf reports flag it, M3.6.1 can introduce a shared singleton (Approach B from brainstorming).
- **Win10 WebView2 Runtime absence**: covered by §3.4 fallback. Bootstrap probe is non-fatal.
